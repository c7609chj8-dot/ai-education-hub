## 3. ID·URL 정합성

- 신규 시연 기수: demo-ai-management-01, demo-ai-music-01, demo-ai-aerial-video-01, demo-ai-multimedia-01, demo-ai-programming-01, demo-ai-advertising-video-01.
- 기존 sample-life/work/ebook/instructor/business는 각각 원래 5개 과정에 연결했다. 해당 페이지에 이전 교육과정 시연임을 표시한다.
- 새 학과 신청 화면의 선택 목록에는 새 기수만 포함한다. 기존 시연 화면의 선택 목록은 이전 과정으로 분리한다.
- sample-advertising은 신규 광고영상 기수로 호환 리디렉션한다.
- 정적 시연 데이터 11개 ID 중복 없음, 호환 주소를 포함한 경로 12개. 실제 UUID는 변경하지 않고 시연 페이지에서도 받지 않는다.
- 권장 slug와 다른 음악 ai-music, 광고영상 ai-advertising-video는 기존 URL을 유지했다. 권장 ai-music-production, ai-ad-video는 별칭으로 새로 만들지 않았다.
- 기존 학과/강좌 상세 주소 11개와 신청 시연 주소를 검사했다. 외부 사이트 링크 전체를 조사한 것은 아니다.

## 6. 확인 범위와 남은 사항

- 실제 관리자 계정으로 교육기수를 저장하거나 실제 신청을 전송하지 않았다. 실제 개발 DB 쓰기 검사도 하지 않았다.
- B-04 검증은 기존 1일차 및 모의 제출/서버 검증 회귀 범위다. 실제 PostgreSQL 동시 마지막 좌석·2일차 트랜잭션 완료를 뜻하지 않는다.
- PGlite는 모델 정합성과 롤백 검사다. 호스팅 실행 권한·자동 RLS 트리거·실제 PostgreSQL 동시성과 후보 SQL 멱등성은 4단계에서 별도 검사한다.
- 현 Supabase의 5개·60주차는 계속 유지된다. 새 6개·72주차는 mock 초안이며 자동 DB 반영되지 않는다.
- 기존 스키마에 주차별 과제·프로젝트·도구/장비 필드가 없다. 상세 메타데이터 저장·공개 조회 방식의 추가 설계/승인이 필요하다.
- 이전 5개 강좌를 비공개로 바꾸면 구 상세 URL 조회가 달라진다. 전환 안내와 공개 해제 정책을 승인받기 전에 상태를 바꾸지 않는다.
- 교육시간·장소·일정·정원·수강료·강사·학위/인가·구체 소프트웨어 이용 조건은 미확정이다.

## 7. 다음 승인과 4단계 계획

[데이터 전환 및 4단계 작업계획](./ai-fusion-stage3-data-plan.md)에 실행 순서와 완료 기준을 작성했다.

1. 실제 개발 DB 기준선·스냅샷·고정 UUID/slug 매니페스트 설계.
2. 신규 6개/72주차 추가 SQL, 실습 상세 메타데이터 구조, 공개 전환 SQL을 분리 설계.
3. 반복 실행·내용 불일치 중단·참조 보존·부분 실패·공개 전환 및 복구 SQL 검증.
4. 실제 PostgreSQL 17 격리 환경에서 소유권·권한·자동 RLS·기존 관리자 v2 회귀 확인.
5. 구체 SQL·영향 건수·미확정 항목·복구안을 보고한 후 실제 개발 DB 적용 별도 승인 요청.

현재 결과는 4단계 SQL 설계·격리 테스트를 검토할 수 있는 상태다. 실제 DB 적용·main 병합·Production 배포 승인은 포함하지 않는다.
