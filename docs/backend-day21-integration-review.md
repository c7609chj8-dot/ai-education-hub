# 백엔드 21일차: 사용자 흐름·동시성·접근성 통합 검수

검수일: 2026년 11월 8일 (한국 시간)

상태: **가상 계정·데이터와 격리된 로컬 PostgreSQL에서 통합 흐름을 검수했습니다. 실제 접수·Supabase·운영 환경 통합 검수는 미완료입니다.**

## 수정 사항

- 강좌 목록과 홈의 ‘과정 안내 보기’ 링크에서 화면 표시 문구가 접근성 이름에 포함되도록 보완했습니다. 기존에는 강좌명을 넣으면서 화면의 ‘과정’이라는 단어가 빠져 음성 제어 사용자가 보이는 문구로 지칭하기 어려웠습니다.
- 일정이 있는 달력 날짜의 접근성 이름 앞에 화면에 표시된 일자를 포함했습니다. 일정이 없는 날짜는 일반 `span`의 `aria-label` 대신 실제 날짜를 담은 `time`과 보조기기용 전체 날짜 텍스트를 사용합니다.
- `scripts/verify-application-concurrency.mjs`에 익명 역할의 공개 강좌·12주 교육내용·공개 기수 조회를 추가하고, 격리 PostgreSQL 종료 후 Windows에서 테스트 프로세스가 정상 종료되도록 정리했습니다.

## 격리 통합 흐름

별도 복사본에서만 개발 프로젝트 주소를 localhost 모의 인증·API로 바꾸고, 강좌 상세에 **검증 전용 신청 링크**와 테스트 전용 신청 라우트를 사용했습니다. 원본 저장소나 서비스에는 이 링크와 라우트를 추가하지 않았습니다. 모의 API는 새로 만든 로컬 PostgreSQL 17 클러스터에 4·8~12·14일차 SQL을 적용하고 가상 강좌·12주 내용·기수·신청 데이터만 사용했습니다. 테스트 후 클러스터를 중지·삭제했습니다.

- 실제 공개 강좌 목록·상세 화면에서 공개 가상 강좌와 12주 내용을 조회하고 비공개 강좌가 보이지 않는지 확인했습니다. 강좌 상세의 일정 링크로 이동해 같은 격리 DB의 공개 기수를 확인했습니다. 실제 일정 화면은 신청이 준비 중이라는 기존 안내를 유지했습니다.
- 상세 화면에서 **복사본에만 삽입된 검증용 링크**로 신청 컴포넌트를 열었습니다. 저장 후 첫 응답 유실을 가정했을 때 결과 미확인과 입력 잠금이 표시되고, 같은 요청을 다시 확인해 DB 신청 한 건만 유지하며 성공을 표시했습니다.
- 가상 관리자로 로그인해 마스킹된 신청 목록에서 확인 처리했습니다. 같은 DB에서 상태·관리자 ID 이력 1건과 정원 유지, 정원이 찬 뒤 다른 신청이 거절되고 성공 화면이 표시되지 않는 것을 확인했습니다. 일반 가상 사용자의 관리자 페이지 접근도 차단됐습니다.
- 브라우저 주소와 로컬·세션 저장소에 가상 신청 이름·연락처가 나타나지 않는지 확인했습니다. JavaScript 비활성화 상태에서 신청 양식을 제출했을 때도 가상 입력값은 URL에 포함되지 않았습니다.

이는 공개 화면·모의 API·로컬 SQL을 연결한 검사입니다. 신청 연결과 가상 인증은 테스트용이므로 **실제 공개 사이트에서 수강신청이 가능한 상태를 증명하지 않습니다.** 브라우저 통합 하네스와 임시 라우트는 이번 검수용 별도 복사본에만 있고 Git에 포함하지 않았습니다.

## 동시성과 접근성

- `npm run test:application-concurrency`: 별도 로컬 PostgreSQL의 두 연결에서 마지막 자리 경쟁, 같은 이름·연락처 중복 신청, 같은 요청 재시도, 관리자 정원 축소·마감 경합, 확인 처리 경합, 이력 실패 롤백과 동일 시각 페이지 이동을 확인했습니다. 테스트에는 저장소 외부의 고정된 `embedded-postgres@17.11.0-beta.19`, `pg@8.23.1`과 `DAY12_PG_MODULE_ROOT` 설정이 필요합니다. 실제 Supabase DB 검사나 부하 검사는 아닙니다.
- 360px에서 본문 바로가기, 모바일 메뉴 열기·Escape 초점 복귀, 달력 날짜 선택, 가상 신청 폼의 키보드 입력과 제출을 확인했습니다. 강좌 목록과 일정 화면은 320·360·768·1440px에서 가로 넘침이 없었습니다. 이 화면 폭 검사는 선택한 화면에 한정됩니다.
- 기존 `axe-core` 4.14.0으로 360px의 강좌 목록, 강좌 상세, 일정, 가상 신청, 관리자 신청 화면을 WCAG 2.0/2.1 A·AA 태그로 검사한 결과 **자동으로 판정된 위반은 0건**이었습니다. 강좌 목록·상세의 장식 화살표와 일정의 이전/다음 달 화살표는 색 대비를 자동 판정하지 못했고, 일정의 이전/다음 달 버튼은 표시 이름 일치 여부도 자동 판정하지 못했습니다. 이 항목들은 수동 확인이 필요합니다. 자동 검사만으로 접근성 준수를 보증할 수 없으며 실제 스크린리더·음성 제어·고대비 모드 사용 검수는 하지 않았습니다.

## 실제 운영 전 남은 사항

- 공개 사이트의 신청 경로와 실제 저장 어댑터는 연결되지 않았습니다. 실제 관리자 계정, Supabase API·RLS, 저장 응답 유실과 동시 접수는 개발 DB 적용 승인 후 다시 검증해야 합니다. 수집 항목·개인정보 안내·보존·삭제 및 악용 방지 정책도 확정이 필요합니다.
- 기존 `public.rls_auto_enable()` 보안 경고 2건, 개발 의존성 중간 등급 8건, 요청 제한·파일 검사와 이력 공백은 여전히 남아 있습니다. 접근성 수동 검수와 다양한 기기·보조기기 확인도 필요합니다.
- 개발 DB와 Storage는 변경하지 않았습니다. 운영 DB, 다른 Supabase 프로젝트, `main`과 Vercel 운영 배포는 변경하지 않았습니다.
