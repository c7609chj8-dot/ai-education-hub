# 백엔드 13일차: 신청 화면·서버 처리 준비

작성일: 2026년 11월 8일

상태: **신청 화면과 서버 제출 흐름의 코드·격리 통합 검증 완료. 실제 접수 연결과 개발 DB 적용은 미완료.**

## 준비한 흐름

- `src/components/applications/application-form.tsx`는 별도로 전달받은 기수와 개인정보 안내를 표시하고 신청·접수 불가·결과 미확인·접수 완료를 구분하는 준비용 컴포넌트입니다. 현재 실제 라우트에 연결하지 않았으며 기존 `/apply/[offeringId]`의 시연 안내는 그대로입니다. 제출 값에 `name` 속성을 부여하지 않아 JavaScript가 꺼진 기본 폼 제출의 URL에 입력값이 담기지 않게 했습니다.
- 저장 응답이 끊기거나 결과가 불분명하면 입력을 잠그고 같은 요청 식별자와 원래 내용을 메모리에서 재전송합니다. 이후 재확인에서도 성공을 확실히 알지 못하면 입력을 잠근 채 담당자 문의를 안내합니다. 페이지 이탈·새로고침 후에는 요청값을 복구하지 않으므로 중복 신청 전 담당자 확인이 필요합니다. 개인정보나 요청값은 브라우저 저장소에 보관하지 않습니다.
- `src/lib/applications/submission.ts`는 신뢰된 서버 안내 버전과 필수 입력·요청 UUID를 확인한 뒤 주입된 저장 함수를 호출합니다. 확정된 저장 성공만 `accepted`로 처리하고 예외나 알 수 없는 결과는 `unknown`으로 처리합니다. 완료 응답에 이름·연락처·DB 식별자를 담지 않습니다. 실제 Supabase 어댑터와 공개 제출 API는 아직 없으며 이 코드만으로 접수를 열 수 없습니다.
- 기수 스냅샷의 사전 상태만으로 재시도를 거부하지 않습니다. 12일차 원자적 트랜잭션이 현재 상태·정원을 잠금 후 검사하고, 이전에 커밋된 동일 요청은 마감 후에도 복구할 수 있도록 하는 설계입니다. 서버 사전 입력 검사는 유지됩니다.

## 검증

`npm run test:application-submission`은 필수 입력·중복 요청 필드·안내 버전, 성공·접수 불가·알 수 없는 결과, 저장 후 응답 유실과 동일 요청 재시도를 가상 저장 함수로 검사합니다. 기존 신청 사전 검증도 다시 실행했습니다.

별도 테스트 전용 Next.js 라우트와 모의 API, 별도 로컬 PostgreSQL 17 클러스터를 연결한 브라우저 테스트에서는 가상 입력으로 다음을 확인했습니다.

- 로컬 DB에 한 건이 커밋된 뒤 응답이 유실돼도, 동일 요청 재확인 시 한 건만 유지하면서 성공 표시.
- DB에서 마감된 기수는 저장되지 않고 접수 불가 안내 표시.
- 응답 유실 뒤 안내 버전이 바뀌어 재확인이 불가능하면 결과 미확인 상태와 입력 잠금 유지.
- 모바일 너비, 브라우저 URL·저장소 개인정보 비노출, JavaScript 비활성 시 입력값의 URL 비포함.

이는 실제 Supabase 서버나 운영 서비스 검사가 아닙니다. 모의 테스트 라우트와 API는 저장소나 서비스에 추가하지 않았습니다.

## 실제 접수 전 필수 작업

1. 8~12일차 DB 초안의 의존 관계·현재 권한·마이그레이션 이력 및 롤백 계획을 확인하고, 별도 승인된 개발 DB 적용과 실제 API·RLS 검증을 수행합니다. 기존 `public.rls_auto_enable()` 경고 2건은 미해결입니다.
2. 기관이 실제 수집 항목·법적 근거·확정된 안내 내용과 버전·동의 방식·보존 및 삭제 정책을 정해야 합니다. 신청자가 본 안내와 서버의 승인된 **변경 불가능한 동일 버전**이 일치하는지 보장해야 합니다. 이 문서의 가상 안내는 실제 수집에 사용하지 않습니다.
3. 관리자 모집 시작·종료 시각 설정, 실제 공개 기수와 모집 기간 검사, 요청 제한·오용 방지, 서버 비밀키 보호, 동시성 및 관리자 경합을 실제 연결에서 검증합니다. 고권한 키는 프로젝트 전반에 권한이 있습니다.
4. 요청 식별자 생성·유효기간·응답 유실 후 사용자의 안전한 복구 절차를 정합니다. 후속 서버 어댑터는 확정된 DB 응답만 성공/접수 불가로 해석하고 전송 오류나 응답 유실을 반드시 미확인으로 처리해야 합니다. 실패·예외 로그와 관측 도구에 개인정보가 남지 않는지도 검증합니다.
5. 위 항목을 검수하고 기능 활성화 및 운영 전환을 별도로 결정하기 전까지는 실제 신청 버튼이나 완료 표시를 공개하지 않습니다. 13일차의 완전한 실제 접수 연결은 보류입니다.

개발·운영 DB, 다른 Supabase 프로젝트, `main` 및 운영 배포를 이번 작업에서 변경하지 않았습니다.
