# 백엔드 23일차: Preview와 데이터 이관 연습

작성일: 2026년 11월 8일 (한국 시간)

## 범위와 기준

- 22일차 브랜치를 기준으로 별도 작업 브랜치에서 검토합니다. Vercel의 비운영 브랜치 배포는 Preview이며, `main` 병합이나 Production 승격은 하지 않습니다. [Vercel 환경 문서](https://vercel.com/docs/deployments/environments)
- 프로젝트 환경변수 목록을 복호화 없이 조회했을 때 프로젝트에 직접 등록된 항목은 없었습니다. 이는 앞으로 추가될 값이나 다른 출처의 설정까지 없음을 보증하지 않으므로, 매 배포 전 연결 대상과 범위를 다시 확인합니다. 확인 당시 Preview에 Vercel 인증 보호가 설정돼 있었습니다.
- 애플리케이션의 기본 데이터 소스는 예시이며, SQL 초안을 개발·운영 DB에 자동 반영하지 않습니다. 예시 일정은 실제 모집 정보가 아닙니다. 실제 신청·문의 접수, 관리자 실계정 인증은 별도의 준비와 검증이 필요합니다.

## 로컬 스키마와 시연 데이터 분리 검증

`npm run test:migration-rehearsal`은 외부 연결 없이 PGlite 메모리 DB 두 개를 새로 만듭니다. 4일차 정식 마이그레이션과 8·9·16일차의 관련 SQL **초안**을 각각 적용한 뒤, 한쪽은 빈 상태로 유지하고 다른 쪽에만 개발용 예시 시드 3개를 적용합니다.

- 빈 DB는 강좌·주차·기수·콘텐츠가 각각 0건입니다.
- 시연 DB는 강좌 5건, 주차 60건, 기수 5건, 콘텐츠 14건입니다. 세 시드를 각각 다시 실행하면 비어 있는 테이블 조건에 따라 거부되며 롤백 후 건수가 유지됩니다. 이는 중복 실행이 성공하는 멱등 시드라는 의미가 아닙니다.
- 이 검사는 행 건수와 시드 거부를 확인하는 국소적인 재현입니다. 두 DB가 독립적이라는 확인이지 실제 Vercel과 Supabase 사이의 데이터 격리나 실데이터 이관 검증은 아닙니다.

기존 `test:backup-recovery`는 별도의 로컬 PostgreSQL 17에서 4일차 정식 SQL과 8~12·14~19일차 초안 11개를 정해진 순서대로 적용하고 복원한 뒤 테이블·제약·RLS·권한 등을 대조합니다. 테스트 전용 SQL 출처 기록은 Supabase의 실제 마이그레이션 이력이 아닙니다. `test:course-access`, `test:schedule-access`, `test:content-database`는 각 예시 시드의 거부 조건과 해당 공개·권한 동작을 격리 환경에서 별도로 확인합니다. 자세한 복원 범위는 [22일차 문서](backend-day22-backup-recovery.md)를 따릅니다.

정식 마이그레이션은 현재 4일차의 `20261107100302_academy_course_foundation` 하나만 개발 DB에 적용된 것으로 기존 검증에 기록돼 있습니다. 이후 SQL은 초안이며 재현 성공만으로 정식 마이그레이션이나 배포 가능 상태가 되지 않습니다. [Supabase 마이그레이션 문서](https://supabase.com/docs/guides/local-development/database-migrations)

## 실제 이관 전 점검 절차

1. 이관 원본·대상 프로젝트 ID와 환경을 확인하고, 운영 데이터와 시연 데이터를 분리합니다. 어떤 실제 개인정보도 연습 데이터에 복사하지 않습니다.
2. 대상의 마이그레이션 이력과 현재 객체·권한·기존 데이터를 읽기 전용으로 비교합니다. 초안의 의존성, 순서, 중복 객체와 롤백·복구 방법을 검토하고 승인된 것만 정식 마이그레이션으로 준비합니다.
3. 빈 일회용 환경에서 전체 적용·권한·중복 시드 차단을 확인합니다. Supabase Auth, Storage 실제 파일·정책, 이벤트 트리거와 API는 이번 로컬 테스트에 포함되지 않으므로 실제 대상에 맞는 별도 검사가 필요합니다.
4. 실제 대상 변경은 별도 승인 후 수행하고, 적용 결과·이력·RLS·접근 권한과 실제 API를 확인합니다. 운영 전에는 백업·복원 권한, 개인정보 처리 기준, 관리자 인증과 운영 환경 분리를 확정합니다.

## 한계와 미해결 사항

- 로컬 검사는 실제 Supabase CLI의 마이그레이션 이력 작성, 원격 적용, 실제 데이터 이관, Auth·Storage·관리자 인증이나 보안 Advisor 재검사를 검증하지 않습니다.
- 기존 `public.rls_auto_enable()` 관련 보안 경고 2건은 이전 검토 기준 미해결입니다. 이번 작업에서 권한이나 함수를 변경하지 않습니다.
- Vercel Preview의 자동 배포와 실제 화면 확인 결과는 PR에서 별도로 기록합니다. 인증 보호와 환경변수 설정은 향후 변경될 수 있으므로 매번 재확인합니다.
- 원격 개발 DB와 운영 DB, 다른 프로젝트 및 Vercel Production에 데이터나 설정을 변경하지 않습니다.
