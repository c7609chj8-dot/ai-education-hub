# DAY 19 프런트엔드 기술 검수

검수일: 2026년 11월 7일. 범위는 실제 개인정보·인증·서버 접수가 없는 프런트엔드 시연입니다.

## 수정한 문제

- 개발 서버를 `127.0.0.1`로 열면 개발용 자원이 차단되어 신청 시연의 입력 검사가 실행되지 않는 경우가 있었습니다. 로컬 호스트 `127.0.0.1`을 개발 서버 허용 목록에 추가하고 `localhost`와 두 주소의 흐름을 다시 확인했습니다. 이 설정은 개발 서버에만 적용됩니다.
- 운영 빌드에서 존재하지 않는 강좌·기수 주소를 처음 요청하면 부분 사전 렌더링 때문에 HTTP 200이 반환되고 이후 요청에서 404가 반환되는 경우가 있었습니다. 현재 고정된 예시 데이터에 맞게 부분 사전 렌더링을 끄고 두 경로를 사전 생성된 항목으로 제한했습니다. 별도로 만든 잘못된 강좌·기수 주소는 최초 및 재요청 모두 404를 반환했습니다. 향후 실제 데이터 기반으로 전환할 때 경로 생성과 404 처리 방식을 다시 설계해야 합니다.

## 검수 결과

- `npx tsc --noEmit`, `npm run lint`, `npm run build`: 통과.
- 로컬 프로덕션 빌드에서 Edge의 360·768·1440px로 25개 화면의 응답, 제목·기본 메타데이터, 주요 레이블, 이미지 대체 텍스트 속성과 가로 넘침을 확인했습니다. 내부 이동 대상 27개는 HTTP 200, 잘못된 일반·강좌·기수 주소는 HTTP 404를 반환했습니다.
- 세 화면 크기에서 메인→강좌→일정→신청 시연→FAQ→문의 시연과 관리자 검색·편집·초점·초기화, 브랜드 미리보기·초기화·공개 화면 분리를 확인했습니다. 본문 바로가기와 모바일 메뉴의 Esc 초점 복귀도 확인했습니다.
- `npm audit --json`: 중간 8건, 높음·심각 0건. `npm audit --omit=dev --json`: 0건. 감사 결과는 검수 시점 기준입니다.

## 남은 사항과 위험도

- **높음 — 실제 운영 전환 시:** 관리자 경로에는 인증이 없고 신청·문의는 실제 접수되지 않습니다. 이는 현재 시연 범위입니다. 실제 개인정보를 사용하거나 운영 서비스를 개시하기 전에 인증·권한, 저장·보호 및 실제 접수 기능의 별도 설계와 구현이 필요합니다.
- **중간 — 개발 의존성:** npm 감사의 중간 등급 8건은 개발 도구 의존성 경로에 묶여 있으며, 공통 원인은 [minimatch의 glob 처리 서비스 거부 권고](https://github.com/advisories/GHSA-g3hv-75wg-m249)입니다. 운영 의존성 감사에서는 발견되지 않았습니다. npm이 제안한 자동 해결에는 주요 버전 변경이 포함되어 있어, 호환성 검토 없이 적용하지 않았습니다.
- **낮음 — 운영 정보:** 실제 연락처·일정·모집 정보는 아직 미정이거나 시연 예시입니다. 운영 정보가 확정되면 교체하고 재검수해야 합니다.
