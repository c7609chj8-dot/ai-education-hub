# 백엔드 18일차: 브랜드·운영 정보

작성일: 2026년 11월 8일

상태: **관리·공개 화면과 SQL 초안 준비, 가상 정보로 격리 검증 완료. 실제 DB에 적용하지 않았습니다.**

## 기능

- 관리자 `/admin/console/brand`에서 브랜드명·대표 문구와 선택적 이메일·전화번호·주소를 관리합니다. 저장할 때마다 서버가 관리자 ID와 개발 프로젝트를 확인합니다. 기본 비공개이며, 공개 상태로 저장한 내용만 공개 화면에 반영됩니다. 공개 체크를 해제하면 기본 브랜드와 연락처 미정 상태로 돌아갑니다. 기존 공개 상태에서 저장하면 변경 사항이 즉시 공개됩니다.
- 브랜드명은 헤더·기관소개·푸터와 페이지 제목에, 대표 문구는 홈 화면에 반영합니다. 연락처·주소는 푸터에 텍스트로 표시합니다. 개발 DB 콘텐츠가 표시될 때는 실제 운영 정보가 아니라는 안내를 추가합니다. 로고·대표 이미지와 SNS 설정은 이번 관리 범위에 포함하지 않습니다.
- 저장은 버전으로 동시 수정 충돌을 감지하고 관리자 ID와 버전을 변경 이력에 기록하도록 설계했습니다. 결과 응답이 유실되면 저장 여부를 확인할 때까지 재저장을 막고 입력 내용을 보존합니다. 고권한 키 보유자의 조작까지 막는 감사 저장소는 아닙니다.
- 기본 데이터 원본은 기존 설정입니다. 개발 환경에서 `ACADEMY_BRAND_SOURCE=supabase`를 빌드 및 실행 환경 모두에 지정하면 개발 프로젝트의 공개 설정을 조회합니다. 데이터가 없을 때는 기본 브랜드를 표시하며, 조회 실패 시 기본 브랜드와 별도 오류 안내를 표시하고 연락처는 숨깁니다. 이 설정으로 빌드하면 레이아웃을 사용하는 페이지가 요청 시 렌더링되므로 캐싱과 성능 영향을 운영 전 평가해야 합니다. 기본값으로 빌드한 뒤 실행 환경 변수만 바꾸면 정적 페이지에서 렌더링 오류가 발생할 수 있으므로 **설정 변경 시 재빌드가 필요합니다**.
- 관리자 기능은 `ACADEMY_ADMIN_BRAND_ENABLED=true`, 지정된 개발 프로젝트 URL, 서버 전용 키가 모두 필요합니다. 환경변수나 키를 설정하지 않았습니다. 서버 전용 키는 프로젝트 전반에 고권한을 갖습니다.

## DB 초안과 검증

`supabase/drafts/day18_brand.sql`은 단일 브랜드 설정·변경 이력, 공개 RLS·뷰 및 서버 전용 함수의 검토용 초안입니다. 익명·인증 역할에는 공개 행의 필요한 열만 읽도록 허용하고, 관리자 조회·수정 함수는 서비스 역할에 제한합니다. 기존 DB에 객체나 정책을 적용하지 않았습니다.

- `npm run test:brand-database`: 별도 로컬 PostgreSQL에서 비공개 기본값, 익명·인증 역할의 관리자 함수 접근 차단, 공개·비공개 전환, 동시 수정 충돌 및 이력 실패 시 롤백을 확인했습니다.
- `npm run test:brand-services`: 가상 정보와 모의 서비스로 관리자·프로젝트·기능 설정 확인, 필드 검증, 공개 여부, 저장 충돌, 공개 정보 실패 처리를 확인했습니다.
- 별도 복사본과 가상 인증·API를 사용한 브라우저에서 저장, 공개·비공개 전환, 헤더·홈·기관소개·푸터·제목 반영, 일반 사용자 요청 차단, 응답 유실 시 중복 저장 방지 및 비활성 모드를 확인했습니다. 실제 Supabase API 검증이 아닙니다.
- TypeScript, ESLint, 빌드 및 기존 서비스 회귀 검사를 수행했습니다.

## 실제 사용 전

8~18일차 SQL 초안은 실제 개발 DB에 적용하지 않았습니다. 실제 데이터·객체·권한과 기존 마이그레이션 이력, 공개 설정을 재검토하고 별도 승인 후 개발 환경에서 적용과 실제 관리자 인증·Data API·RLS 검증이 필요합니다. 실제 연락처·주소와 공개 승인자는 기관이 확정해야 합니다. 기존 `public.rls_auto_enable()` 보안 경고 2건은 미해결입니다. 운영 DB, 다른 Supabase 프로젝트, `main`과 운영 배포는 변경하지 않았습니다.
