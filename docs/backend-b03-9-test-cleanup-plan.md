# B-03-9 시험 기수 정리 검토 — 실행 보류

기준: PR #33 `bca2fa291e82b949476f5abeda97b29e1fbc180a`. 이 문서와 `.psql.txt`는 검토용이다. 실제 개발 DB 삭제·복원, 마이그레이션, 역할·RLS·GRANT 변경은 수행하지 않았다. 사용자 확인 결과 외부 연결 여부를 판단하기 어렵다. 따라서 외부 참조가 없다고 가정하거나 실행 게이트를 설정해서는 안 된다.

- 시험 기수 `e9791c02-5bbf-4b55-86e3-7b6302cd6711`: 강좌 `7057c1b5-ff56-41e1-8d1a-63938f11a529`, draft, 비공개, 장소 `B-03-6 개발 시험 (수정)`, 정원 10. 교육 2027-03-02~05-18, 모집 한국 시간 2027-02-01 09:00~02-28 18:00.
- 개발 DB의 기수 외래키 참조와 신청·결제·출석 계열 이름의 테이블, 기수 관련 이름의 열은 검색 범위에서 발견되지 않았다. 이름 기반 검색은 JSON·다른 이름·외부 시스템의 참조 부재를 증명하지 못한다. 미적용 신청 SQL에는 향후 기수 참조가 있다.

- 실제 익명 Data API: 공개 강좌 5, 주차 60, 공개 일정 0, 해당 시험 UUID 0. 비로그인 관리자 API HTTP 401. 관리자 세션의 기수 화면에서 강좌 5개와 비공개 시험 기수 표시를 확인했다. PC 1280×800과 모바일 390×844에서 폼과 메뉴 표시를 확인했다. 일반 사용자 실제 JWT HTTP 403은 B-03-8 기록이 있으며 이번 실행에서는 별도 세션을 확보하지 못해 재검증하지 않았다.

## 삭제 방식 비교

| 방식 | 장점 | 위험과 승인 |
| --- | --- | --- |
| DB 관리자 일회성 트랜잭션 | 한 행만 정리하고 상시 삭제 API·역할·정책을 추가하지 않음 | 실제 `postgres`는 BYPASSRLS. 이전 지시의 RLS 우회 금지와 관계되므로 명시적 예외 승인 전 실행 불가. 외부 참조도 별도로 확인해야 함. |
| 전용 비우회 역할·정책 | RLS를 유지하는 별도 설계 가능 | 역할, 정책, GRANT 및 제거 절차 등 DB 구조 변경이 필요하고 새로운 권한 면이 생김. 별도 검토·승인 없이는 배포 불가. |

일회성 관리자 방식이 영구 변경은 가장 적지만, 사용자에게 외부 참조를 확인하기 어렵다는 답변을 받은 현 상태에서 안전한 실행으로 판정할 수 없다. 일반 관리자 삭제 API는 추가하지 않는다.

- psql 17용 파일이며 정식 마이그레이션이 아니다. 삭제는 정확한 UUID·강좌·장소·상태·비공개 여부와 11개 열 전체 스냅샷을 비교하고, 이력·행 수·참조·트리거·스키마 변경을 보수적으로 검사한다. 이후 한 트랜잭션에서 1건만 삭제한다. 각 조건 오류 시 중단한다.
- `b039_execute`와 `b039_external_clear`는 운영자의 수동 선언일 뿐 외부 참조 검사 결과가 아니다. 외부 참조 검증이 되기 전 어떤 플래그도 실제 DB에서 설정하지 않는다. 복원은 별도의 `b039_restore` 확인과 별도 승인 대상이다.
- `postgres`/DB 이름과 백업의 프로젝트 문자열은 실제 연결된 프로젝트를 증명하지 못한다. 추후 실행 전 IPv4 Session Pooler의 호스트·프로젝트 사용자명 `postgres.uenvjqgylrevujdjpfed`, 대상 DB, 인증서 및 TLS `verify-full`을 안전한 실행 절차로 별도 확인해야 한다. 해당 원격 실행 래퍼 및 원격 dry-run은 아직 준비·검증되지 않았다. 비밀번호를 인수·로그·저장소에 남기지 않는다.
- 기수 테이블 ACCESS EXCLUSIVE 잠금은 다른 읽기·쓰기에도 영향을 줄 수 있다. 잠금 제한 3초, 문장 제한 30초이나 실제 호스팅 잠금·동시성은 미검증이다. 외부 서비스 및 외래키 없는 비동기 쓰기를 잠금만으로 통제할 수 없다.
- 참조가 있거나 변경·오류가 발생하면 중단한다. 오류·타임아웃으로 커밋 여부가 불명확하면 재실행하지 않고 별도 읽기 전용 연결로 UUID와 실제 상태를 확인한다. 실제 복구는 원인 분석과 별도 승인 후 수행한다.

- 저장소 외부 `backup-20261109-223910`의 4개 파일 해시는 확인했다. 이 전체 백업은 시험 기수 생성 전이며 기수 0건이다. Auth/Storage/호스팅 역할·이벤트 트리거의 실제 호스팅 복원은 미검증이다.
- 저장소 외부 `b038-test-offering-snapshot-20261110-222128/offering-test-row.json`의 SHA-256 `d4ffe182b4de7d2d3e8f48c03c46f0e4c517b68ea5c62b386ebc200ac30a04af`와 현재 행 11개 열의 일치를 확인했다. 단일 행 스냅샷은 전체 백업이 아니다. 실행 직전 다시 해시와 모든 열을 확인해야 하며 해시 파일 자체는 위변조 방지 서명이 아니다. 덤프·스냅샷 내용과 민감정보는 GitHub나 채팅에 올리지 않는다.
- localhost PostgreSQL 17.11의 가상 행으로 후보 psql 파일을 시험했다. 승인 누락, 외부 검토 플래그 누락, 스냅샷 불일치, FK, 잠금 충돌은 실패하고 행이 유지됐다. 삭제 후 오류를 주입하면 롤백됐고, 가상 1건 삭제 및 별도 허용 후 전체 행 복원이 일치했다. 실제 DB 삭제·복원이나 실제 호스팅 권한 시험은 아니다.
- `npm run build`, TypeScript, ESLint와 관리자 권한·저장·입력·동시성·오류 응답 관련 격리 회귀 검사를 통과했다. PostgreSQL 테스트 재실행에는 저장소 외부 고정 테스트 모듈을 `DAY12_PG_MODULE_ROOT`로 지정해야 한다. 지정하지 않은 한 차례 재실행은 의존성 경로 누락으로 시작하지 못했다.

## HTTP 500과 후속 일정

기존 HTTP 500 및 `Unexpected end of JSON input`의 원인은 재현·확정되지 않았다. B-03-8의 민감정보 없는 진단과 빈 본문·잘못된 JSON·인증·RPC 오류 분기 회귀 테스트는 통과했지만 과거 장애가 완전히 해결됐다는 뜻은 아니다.

1. 외부 연동 담당자·관리 콘솔 접근권한을 확보해 신청·결제·출석 및 웹훅 등 참조를 확인하고 증거를 남긴다. 확인이 불가능하면 비공개 시험 기수를 유지한다.
2. 외부 참조가 없고 원격 실행·백업·잠금 조건이 검토된 경우에만 기존 RLS 우회 제한에 대한 명시적 예외를 포함한 **삭제 승인**을 별도로 요청한다. 단순 승인 플래그로 미확인을 해결하지 않는다.
3. 삭제 후 UUID, 기수 수, 공개 API, 강좌·주차, Auth·관리자 권한을 검증한다. 복원이 필요하면 별도 승인 후 동일 스냅샷으로 한 행만 복원한다.
4. 이후 Preview 환경에서 인증·신청·문의·정원·콘텐츠 통합과 개인정보·백업 복원 검수를 진행하고, 운영 정보와 환경 분리 확인 뒤 별도 운영 전환 결정을 받는다.
