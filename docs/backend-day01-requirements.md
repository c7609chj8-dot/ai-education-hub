# 백엔드 1일차 요구사항 정리

작성일: 2026년 11월 7일

상태: **요구사항 정리 초안 — 미확정 운영 정책은 결정 후 반영**

## 1. 목적과 현재 상태

에이담 AI아카데미의 프런트엔드 시연을 실제 교육 운영에 사용할 수 있도록 수강신청·문의·관리자 업무의 범위와 판단이 필요한 정책을 정리합니다. 이 문서는 구현 명세의 출발점이며 데이터베이스나 실제 접수 기능을 생성하지 않습니다.

현재 사이트의 강좌·일정은 예시 데이터이고 신청·문의는 입력 시연입니다. `/admin/demo`는 로그인 없는 시연 화면이며 실제 관리자가 아닙니다. GitHub `main`은 Vercel 운영 배포에 연결되어 있습니다. 사용자 요청에 따라 **실제 수강신청은 비회원 신청부터 시작**합니다.

## 2. 결정 상태와 기본 원칙

| 항목 | 상태 | 내용 |
| --- | --- | --- |
| 신청자 이용 방식 | **확정** | 비회원 신청부터 시작. 수강생 회원가입·로그인은 초기 범위에 넣지 않음 |
| 프런트엔드 우선 | **확정** | 이미 배포된 화면을 기반으로 백엔드를 별도 단계에서 연결 |
| Supabase | **계획** | 데이터·관리자 인증은 Supabase 기반으로 설계. 실제 프로젝트·환경은 아직 선택하거나 연결하지 않음 |
| 환경 분리 | **확정** | 개발 DB와 운영 DB를 분리. 실제 프로젝트·소유 계정·예산은 미정 |
| 정원·중복 | **확정** | 실제 접수 즉시 자리 확보. 같은 기수·같은 이름·연락처의 중복 신청 방지. 세부 비교·취소 규칙은 미정 |
| 개인정보·보존·취소 | **미확정** | 수집 항목, 보존 기간, 동의 문구, 본인 확인 및 취소 절차는 기관 결정 필요 |
| 관리자 역할 | **제안** | 기관 관리자·운영 담당자로 나누는 안. 실제 담당자와 권한은 미확정 |
| 문자·이메일 자동 발송 | **기본 범위 제외** | 필요성과 제공업체·비용이 정해지면 별도 계획 |

원칙: 개인정보는 목적에 필요한 최소한으로 정하고, 실제 데이터는 개발·테스트에 사용하지 않습니다. 공개 시연은 실제 접수 준비와 검수가 완료될 때까지 시연 상태를 유지합니다. 기존 `/admin/demo`에 실제 개인정보를 넣지 않습니다.

## 3. 운영 흐름 초안

### 3.1 강좌 탐색과 비회원 신청

1. 방문자가 공개된 강좌와 기수·모집 상태를 확인합니다.
2. 신청 가능한 기수를 선택하고, 기관이 확정한 필수 정보와 개인정보 안내를 확인합니다.
3. 서버는 입력값·접수 가능 기간·모집 상태·중복 기준을 검사합니다.
4. 서버와 DB는 정원 확인과 신청 저장을 일관되게 처리합니다. 남은 자리가 하나일 때 동시 요청이 와도 정원을 넘지 않아야 합니다.
5. 저장이 실제로 성공한 경우에만 **신청 접수 완료**를 표시합니다. 접수 완료는 교육 확정이나 결제 완료를 의미하지 않습니다. 실패·마감·중복은 각각 안내합니다.
6. 운영 담당자가 권한에 따라 신청을 확인하고 기관이 정한 상태로 처리합니다.

**아직 결정되지 않은 부분:** 비회원이 본인 신청 내역을 어떻게 조회·취소할지와 본인 확인 방식. 이 정책이 정해지기 전에는 이름·전화번호만으로 신청을 조회·수정·취소하는 기능을 만들지 않습니다. 초기에는 운영 담당자가 별도 검증된 절차로 처리하는 안을 검토할 수 있으나, 본인 확인 수단과 절차는 확정 전입니다.

### 3.2 문의

1. 방문자가 문의 유형과 내용을 작성하고 확정된 개인정보 안내를 확인합니다.
2. 서버가 필수 입력과 오용 방지 조건을 확인하고 저장에 성공했을 때만 접수 완료를 표시합니다.
3. 권한 있는 담당자가 문의를 확인하고 처리 상태를 변경합니다.
4. 발송 채널과 담당자 응답 방식은 기관이 정합니다. 자동 이메일·문자는 현재 기본 일정에 포함되지 않습니다.

### 3.3 관리자 운영

1. 기관이 지정한 관리자가 실제 관리자 페이지에서 로그인합니다. 시연 경로 `/admin/demo`와 실제 관리 경로는 분리합니다.
2. 서버에서 세션과 역할을 확인한 뒤 허용된 강좌·일정·신청·문의·콘텐츠만 접근합니다.
3. 신청·문의 및 공개 콘텐츠의 주요 변경은 수행자·시각·대상·행위 등 필요한 범위의 이력을 남깁니다. 이력에 문의 내용이나 연락처를 불필요하게 복제하지 않습니다.
4. 로그아웃, 세션 만료, 권한 회수와 계정 복구 절차를 검수합니다.

## 4. 역할과 권한 초안

아래 역할은 **제안**이며 담당자 수와 업무 분리는 기관이 결정합니다. 권한은 화면 표시뿐 아니라 서버 요청과 데이터 접근에서도 확인합니다.

| 역할 | 공개 정보 | 신청·문의 | 강좌·일정·콘텐츠 | 관리자 계정·권한 |
| --- | --- | --- | --- | --- |
| 방문자·비회원 | 공개된 정보 조회 | 신청·문의 작성만. 타인 자료 조회·수정 불가 | 관리 불가 | 접근 불가 |
| 운영 담당자 | 조회 | 담당 업무에 필요한 조회·처리 | 허용받은 범위에서 관리 | 관리 불가 제안 |
| 기관 관리자 | 조회 | 기관 업무에 필요한 조회·처리 | 관리·공개 설정 | 지정된 절차에 따른 관리 제안 |

비회원 본인 조회·취소는 본인 확인과 권한 모델을 별도로 결정하고 검수하기 전까지 제공 범위 미확정입니다. 데이터 접근은 기본 거부를 기준으로 설계하고, Data API를 사용하는 대상에 대해서는 객체 접근 권한과 RLS 정책을 함께 검사합니다.

## 5. 수집·운영 데이터 후보

**아래 표는 기존 시연 화면과 기능을 토대로 한 후보이며, 실제 필수 수집 항목이나 법적 근거가 확정된 것은 아닙니다.** 주민등록번호, 건강정보 등 민감하거나 과도한 항목은 현재 요구사항에 포함하지 않습니다.

| 구분 | 후보 항목 | 사용 목적·비고 | 결정 상태 |
| --- | --- | --- | --- |
| 강좌·기수 | 과정명·교육내용·모집 기간·정원·장소·상태 | 공개 교육정보와 신청 가능 여부 표시 | 실제 운영값 미정 |
| 신청자 정보 | 성명·연락처 | 신청자 식별 및 운영 안내 후보. 다른 항목은 필요성 확인 후 결정 | 필수 여부·중복 비교의 세부 규칙 미정 |
| 신청 처리 | 기수 식별자·접수 시각·처리 상태·취소 이력 | 접수·정원·처리 이력 관리 | 상태와 정원 산정 규칙 미정 |
| 문의 | 문의 유형·이름·이메일·내용 | 현재 시연 폼의 항목. 실제 운영에 필요한 항목만 선택 | 필수 여부·응답 채널 미정 |
| 개인정보 안내 | 안내 문구·적용 버전·확인 시각 등 | 확정된 수집 근거와 안내 이력 검토 | 근거·문구·보존 기간 미정 |
| 관리자·이력 | 계정 식별자·역할·대상·행위·시각 | 권한 관리와 업무 추적. 불필요한 개인정보 복제 금지 | 역할·접근 범위 미정 |
| 자료·성과 | 제목·공개 상태·파일 경로·권한 | 실제 자료와 공개 범위 관리 | 공개·비공개 및 파일 정책 미정 |

개인정보 수집·이용의 법적 근거와 공지·동의 방식, 보유·이용 기간, 삭제·열람 처리 및 위탁 여부는 실제 운영 사실에 맞춰 기관에서 확정하고 필요한 검토를 거쳐야 합니다. 이 문서에 특정 기간을 임의로 정하지 않습니다. 참고: [개인정보 보호법 제15조](https://law.go.kr/LSW/lsLawLinkInfo.do?ancYnChk=0&chrClsCd=010202&lsJoLnkSeq=1006184341), [개인정보 포털 안내](https://www.privacy.go.kr/front/contents/cntntsView.do?contsNo=36).

## 6. 기능 요구사항과 확인 기준

| ID | 요구사항 | 확인 기준 |
| --- | --- | --- |
| R01 | 비회원은 공개 강좌·기수 확인 후 신청 가능 | 로그인 없이 신청 흐름에 접근하고 비공개 기수에는 신청 불가 |
| R02 | 실제 저장이 성공한 경우에만 접수 완료 표시 | 저장 실패·시간 초과 시 접수 완료로 표시하지 않음 |
| R03 | 정원과 중복 요청을 서버·DB에서 검증 | 접수 즉시 자리 확보; 같은 기수·이름·연락처의 동시 신청에서 초과·중복 없음. 비교 세부 규칙은 별도 확정 |
| R04 | 비회원에게 다른 신청·문의 내용을 노출하지 않음 | 식별자 추측·직접 요청·권한 없는 목록 조회 차단 |
| R05 | 관리자 로그인과 역할을 서버에서 검증 | 로그아웃·만료·일반 방문자·권한 없는 역할을 차단 |
| R06 | 강좌·기수·공지·FAQ·성과·파일은 공개 범위에 맞춰 관리 | 비공개 항목과 파일은 공개 방문자에게 노출되지 않음 |
| R07 | 문의는 저장 결과와 처리 상태를 구분 | 실패와 성공을 구분하고 권한 있는 담당자만 확인 |
| R08 | 동의·안내와 보존·삭제는 확정된 정책을 적용 | 정책 버전·수집 근거 및 삭제·복구 절차를 운영 전 검토 |
| R09 | 관리자 주요 변경은 필요한 범위에서 추적 | 승인된 담당자의 변경 대상·시각·행위를 확인할 수 있음 |
| R10 | 개발·미리보기·운영을 분리 | 테스트 요청이 운영 DB에 쓰이지 않고 비밀키가 브라우저·저장소에 노출되지 않음 |
| R11 | 예시 화면과 실제 운영 기능을 구분 | 실제 기능 검수 전에는 시연 안내 유지; 실제 관리자와 `/admin/demo` 분리 |

## 7. 미확정 사항과 결정 시점

결정 담당자는 **기관 운영 책임자(구체적인 담당자 미지정)**를 기본 제안으로 두며, 실제 담당자는 기관에서 지정합니다. 기한은 제안 일정 기준이며 결정이 늦어지면 후속 설계·구현 일정이 달라집니다.

| 번호 | 결정 사항 | 선택지·검토 내용 | 결정 필요 시점 | 담당 |
| --- | --- | --- | --- | --- |
| D01 | 신청·문의 필수 항목 | 성명·연락처·이메일 등의 필요성과 목적 | 데이터 설계 전, 3일차 | 기관 운영 책임자 지정 필요 |
| D02 | 비회원 조회·취소 | 온라인 기능 제공 여부, 본인 확인 수단, 운영자 처리 절차 | 신청 설계 전, 3일차 | 기관 운영 책임자 지정 필요 |
| D03 | 중복·정원·취소 | 확정된 동일 기수·이름·연락처 기준의 표기 차이, 대기자, 취소 기한과 정원 복귀 | 신청 설계 전, 3일차 | 기관 운영 책임자 지정 필요 |
| D04 | 개인정보 | 수집 근거·안내 문구·동의 여부·보존 기간·삭제와 열람 대응 | 실제 접수 구현·운영 전 | 기관 개인정보 담당자 지정 필요 |
