# 백엔드 16일차: 공지·FAQ·교육협력 콘텐츠 관리

작성일: 2026년 11월 8일

상태: **관리·공개 화면 및 SQL 초안 준비, 격리 검증 완료. 개발 DB 적용과 실제 Supabase API 검증은 대기.**

## 구현 범위

- 관리자 `/admin/console/content`에서 공지·FAQ·교육협력 콘텐츠의 등록·수정·표시 순서·공개 여부를 관리합니다. 새 콘텐츠는 기본 비공개이며, 저장할 때 검증된 관리자와 버전을 이력에 기록하는 SQL 초안입니다. 동시 편집으로 버전이 달라지면 덮어쓰지 않고 충돌을 안내하며, 입력 중인 내용은 유지합니다. 저장 응답이 유실되면 중복 등록을 막기 위해 재저장을 잠그고 목록 확인을 안내합니다. 삭제는 제공하지 않습니다.
- 관리자 페이지와 저장 요청은 각각 관리자 인증을 확인합니다. `ACADEMY_ADMIN_CONTENT_ENABLED=true`, 서버 전용 키 및 지정된 개발 프로젝트 URL이 모두 맞을 때만 관리 API 호출을 시도합니다. 기능은 기본 비활성화되어 있으며 환경변수나 키를 설정하지 않았습니다. 고권한 키는 프로젝트 전반에 권한이 있습니다.
- 공지·FAQ·교육협력은 기본적으로 기존 시연 화면을 표시합니다. `ACADEMY_CONTENT_SOURCE=supabase`에서는 승인된 개발 프로젝트의 공개 콘텐츠만 조회합니다. 개발 프로젝트 데이터에는 항상 시연 표시를 붙입니다. 비공개 항목은 표시하지 않고, 빈 결과와 오류를 구분하며 오류 시 시연 데이터로 대체하지 않습니다.
- 기존 FAQ 링크는 `/programs`, `/schedule`, `/partnership`, `/contact` 중 하나의 내부 경로와 표시 문구를 함께 지정하는 방식으로 보존합니다. 외부 주소와 다른 콘텐츠 유형의 링크는 거부합니다. 교육협력 화면에는 기존 문의 시연 경로를 유지합니다. 콘텐츠 본문은 HTML로 실행하지 않고 텍스트로 표시합니다.

## DB와 개발 예시

`supabase/drafts/day16_content_management.sql`은 콘텐츠·변경 이력 테이블, 공개 RLS와 `security_invoker` 뷰, 관리자 함수의 **검토용 초안**입니다. 공개 역할은 공개 콘텐츠의 필요한 열만 읽으며 관리자 함수는 서비스 역할만 실행하도록 설계했습니다. 변경 이력은 고권한 키 보유자까지 위조·변조할 수 없는 감사 저장소가 아닙니다.

`supabase/drafts/day16_dev_content_examples.sql`은 사용자가 선택한 기존 시연 공지 3건·FAQ 5건·교육협력 예시 6건의 개발 전용 초안입니다. 검증용으로 공개 상태가 지정되어 있으나 실제 운영 정보가 아닙니다. 빈 테이블과 잠금을 확인하는 별도 트랜잭션이며 자동 실행하지 않습니다. 운영 DB에는 적용하지 않습니다.

현재 공개 목록은 유형별 최대 200건까지 허용하며 그보다 많으면 일부를 조용히 누락하지 않고 오류로 처리합니다. 대량 콘텐츠용 공개 페이지 나누기는 후속 작업입니다. 관리자 목록은 20건씩 페이지를 나눕니다.

## 검증

- `npm run test:content-database`: 별도 PostgreSQL 17에서 예시 데이터의 동시 중복 실행 차단, 공개·비공개 조회 권한, 관리자 함수 차단, 공개 전환, 동시 편집 충돌, 이력 실패 롤백과 내부 링크 제약을 확인했습니다.
- `npm run test:content-services`: 관리자 ID·기능 설정·개발 프로젝트 확인, 입력·날짜·내부 링크 검증, 담당자 위조 차단과 충돌 응답을 확인했습니다.
- 별도 복사본에서만 개발 URL 고정을 로컬 모의 인증·API로 바꿔 브라우저 검사를 수행했습니다. 공지·FAQ·교육협력 표시, 등록·공개·비공개 전환, 편집 충돌과 저장 응답 유실 시 입력 보존·재저장 차단, 안전한 텍스트 표시, 기존·신규 FAQ 링크, 빈 결과·오류, 일반 사용자 직접 요청 차단과 기본 시연 모드를 확인했습니다. 실제 Supabase 검사가 아닙니다.
- TypeScript, ESLint, 전체 빌드와 기존 신청·문의·관리자·강좌·일정 회귀 검사를 수행했습니다.

## 실제 사용 전 남은 작업

8~16일차 SQL과 개발 예시는 실제 개발 DB에 적용되지 않았습니다. 현재 객체·권한·마이그레이션 이력과 롤백을 검토한 뒤 별도로 승인된 개발 DB 적용 및 실제 관리자 계정·Data API·RLS 검증이 필요합니다. 실제 공지와 협력 정보의 작성·승인자, 게시 기준, 변경 이력 보존, 운영 전환은 기관이 확정해야 합니다. 기존 `public.rls_auto_enable()` 보안 경고 2건은 미해결입니다. 운영 DB, 다른 Supabase 프로젝트, `main`과 운영 배포는 변경하지 않았습니다.
