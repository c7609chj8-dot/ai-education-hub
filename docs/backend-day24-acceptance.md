## 운영자 인수 시험안

실제 DB 적용과 개인정보 수집은 별도 승인된 개발 환경과 가상 데이터로 먼저 시험합니다. 각 시험마다 담당자·일시·대상 프로젝트와 배포 커밋·결과·결함·재시험 결과를 기록하고, 증거에 개인정보나 키를 남기지 않습니다.

| 순서 | 운영자가 확인할 기준 | 현재 상태 |
| --- | --- | --- |
| 1 | 브랜드명·기관소개·강좌 내용·교육 장소·일정·정원·연락처가 승인된 실제 정보와 일치 | 브랜드명 `에이담 AI아카데미`만 확정. 연락처·주소·일정·담당자 미정; 시연 유지 |
| 2 | 신청 가능 일정과 마감·정원·중복 신청, 입력 오류, 성공·마감·결과 미확인 및 재확인 안내가 실제 업무 기준과 일치 | 가상 로컬 검사만 완료; 실제 저장 경로 미연결 |
| 3 | 문의 접수, 담당자 확인·상태 변경 및 실제 답변 경로가 기관 업무 방식과 일치 | 가상 서비스 검사만 완료; 실제 접수·답변 경로 미확정 |
| 4 | 승인된 관리자만 로그인·조회·수정하고 비관리자는 차단되며 만료·회수 후 접근이 제한됨 | 실제 계정·세션·Data API 시험 미완료 |
| 5 | 비공개 강좌·콘텐츠·파일과 신청·문의 개인정보가 허용되지 않은 역할에 노출되지 않음 | 일부 격리 테스트만 완료; 실제 정책·Storage·API 시험 미완료 |

## 운영 전 반드시 해결할 항목

1. 실제 운영 정보, 개인정보 처리 기준·담당자, 운영 계정 및 개발·운영 환경 분리를 확정합니다. 운영 정보는 미정이라는 기관의 답변에 따라 계속 시연으로 표시합니다.
2. 8~19일차 SQL 초안의 객체·권한·적용 순서·기존 DB 이력·복구 방안을 다시 검토하고 별도 승인된 개발 DB에 적용·검증합니다. 실제 관리자 계정과 Data API·RLS·Storage를 확인한 뒤 운영 환경 전환을 따로 설계해야 합니다. 현재 공통 Supabase 설정은 개발 프로젝트에 고정되어 있습니다.
3. 신청·문의의 실제 저장 연결과 개인정보 안내, 요청 제한·악용 방지, 응답 유실·중복·정원 경합·감사·로그를 실제 연결에서 검수합니다. 현재 보이는 신청·문의 완료는 시연 확인입니다.
4. `public.rls_auto_enable()`의 외부 실행 권한 경고 2건을 자동 RLS 영향과 함께 별도 검토·처리합니다. 기존 함수·이벤트 트리거를 임의로 수정하거나 삭제하지 않습니다.
5. 파일 검사·악성코드 대응, 관리자 권한과 키 관리, 백업·복원, 운영 모니터링, 미완료 접근성 검수와 의존성 보안 검토를 마칩니다. [Supabase 운영 준비 체크리스트](https://supabase.com/docs/guides/deployment/going-into-prod)를 실제 설정에 맞게 별도 확인합니다.
