# 백엔드 15일차: 문의 접수와 관리자 처리

작성일: 2026년 11월 8일

상태: **문의 접수·관리자 처리 코드와 DB 초안 준비, 격리 검증 완료. 실제 문의 접수·개발 DB 적용은 미완료.**

## 준비한 기능

- 기존 문의 시연의 유형·이름·이메일·문의 내용을 후보 입력으로 사용해 서버에서 필수 항목·형식·길이·안내 버전·확인 여부를 검사합니다. 실제 필수 수집 항목과 개인정보 수집 근거·안내 문구·보존 기간은 기관이 확정해야 합니다.
- `src/components/inquiries/inquiry-form.tsx`는 성공·접수 불가·결과 미확인을 구분하는 준비용 화면입니다. 응답 유실 시 같은 요청 ID와 내용을 메모리에서 재전송하며, 결과가 불명확하면 입력을 잠급니다. URL과 브라우저 저장소에 문의 내용을 저장하지 않습니다. 공개 라우트나 실제 저장 어댑터에 연결하지 않았고 기존 `/contact`는 시연으로 유지됩니다.
- `/admin/console/inquiries`는 서버에서 검증한 관리자만 조회·상세 보기·상태 변경을 요청할 수 있습니다. 목록은 이름을 마스킹하고, 상세 조회는 필요한 이름·이메일·문의 내용을 별도 요청으로 표시합니다. 검색어는 URL이 아닌 요청 본문으로 전송합니다. 상세 보기와 상태 변경은 각각 검증된 담당자 ID와 시각을 기록합니다.
- 문의 상태는 기존 설계의 `접수 → 처리 중 → 처리 완료`를 임시 구현했습니다. 이는 운영 정책 확정 전 후보이며 메일·문자 발송이나 답변 전달을 수행하지 않습니다. 취소·재개 및 삭제도 제공하지 않습니다.
- 관리자 기능은 `ACADEMY_ADMIN_INQUIRIES_ENABLED=true`, 관리자 허용목록, 서버 전용 키와 지정된 개발 프로젝트 URL이 모두 맞을 때만 호출합니다. 기본 비활성 상태이며 이번 작업에서 환경변수·키를 설정하지 않았습니다.

## DB 초안과 접근 통제

`supabase/drafts/day15_inquiries.sql`은 **검토용 초안**으로, 문의 메타데이터·개인정보 본문·접근/상태 이력을 분리합니다. 세 테이블에 RLS를 적용하고 anon/authenticated의 직접 접근과 함수 실행을 차단하도록 했습니다. 서버 전용 서비스 역할이 제한된 함수들을 호출하며, 동일 요청 ID와 내용의 재전송은 한 건만 저장합니다.

상세 조회 기록이 저장되지 않으면 상세 응답도 반환하지 않고, 상태 변경 이력이 저장되지 않으면 변경도 롤백합니다. 이력에는 문의 ID·담당자 ID·행위·상태·시각만 남기고 본문이나 이메일은 복제하지 않습니다. 다만 고권한 서비스 키를 가진 주체까지 이력을 위조·변조할 수 없는 저장소는 아닙니다. 목록 검색 자체의 접근 이력과 관리자별 세분화된 권한도 후속 검토가 필요합니다.

## 검증

- `npm run test:inquiry-database`: 별도 PostgreSQL 17의 두 연결에서 중복 요청, 익명·일반 사용자 차단, 저장 실패 롤백, 마스킹 목록, 상세 접근 이력, 상태 이력 실패 롤백, 동시 변경과 동일 시각 페이지 이동을 확인했습니다.
- `npm run test:inquiry-services`: 유효하지 않은 문의·중복 필드·미확정 안내 차단, 응답 유실 재시도, 관리자 ID·기능 설정·개발 프로젝트 확인과 담당자 위조 차단을 확인했습니다.
- 로컬 PostgreSQL 테스트 재실행에는 저장소 외부 테스트 폴더의 `embedded-postgres@17.11.0-beta.19`, `pg@8.23.1`과 `DAY12_PG_MODULE_ROOT` 설정이 필요합니다. 실제 DB 주소는 사용하지 않습니다.
- 별도 복사본에서만 개발 URL 고정을 로컬 모의 인증·API 주소로 바꿔 브라우저 검사를 수행했습니다. 마스킹 목록, 상세·상태 처리, 일반 사용자의 직접 요청 차단, 기능 비활성화, 가상 문의의 응답 유실 재시도와 JavaScript 비활성 시 URL 비노출을 확인했습니다. 실제 Supabase 검사가 아닙니다.
- TypeScript, ESLint, 전체 빌드 및 기존 신청·관리자·강좌·일정 회귀 검사를 수행했습니다.

## 실제 연결 전 필요 사항

개인정보의 실제 수집 항목·법적 근거·안내 및 동의 방식·보존과 삭제, 문의 처리 상태와 답변 경로, 담당자 권한과 이력 보존 정책을 확정해야 합니다. 악용 방지·요청 제한, 서버 비밀 키 보호와 플랫폼 로그의 개인정보 노출, 응답 유실 후 복구 절차도 검증해야 합니다. 8~15일차 SQL은 실제 개발 DB에 적용되지 않았으며, 적용 전 객체·권한·마이그레이션 이력·롤백 검토 및 별도 개발 DB 적용 절차가 필요합니다. 실제 관리자 계정과 Supabase Data API는 미검증입니다.

기존 `public.rls_auto_enable()` 보안 경고 2건은 미해결입니다. 운영 DB, 다른 Supabase 프로젝트, `main`과 운영 배포는 변경하지 않았습니다.
