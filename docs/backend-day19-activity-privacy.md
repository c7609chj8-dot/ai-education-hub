# 백엔드 19일차: 관리자 작업 이력과 개인정보 처리 준비

작성일: 2026년 11월 8일

상태: **이력 조회 코드·SQL 초안과 수동 처리 절차 준비, 가상 데이터로 격리 검증 완료. 실제 DB 적용 및 개인정보 삭제 기능은 미완료.**

## 이력 조회 범위

관리자 `/admin/console/audit`에서 기존 초안에 기록되는 신청 상태 변경, 문의 상세 조회·상태 변경, 콘텐츠·자료·브랜드 저장 이력을 유형별로 조회합니다. 결과에는 이력 시각, 행위, 담당자 ID, 대상 ID와 가능한 상태·버전만 표시합니다. 신청자 이름·연락처, 문의 본문·이메일, 콘텐츠와 파일 내용은 반환하지 않습니다. **담당자·대상 ID도 다른 정보와 결합해 개인을 식별할 수 있으므로 보호 대상입니다.** 이력 목록의 커서는 URL이 아닌 서버 요청으로 전달합니다.

이력 조회는 매 요청마다 관리자 ID 허용목록, `ACADEMY_ADMIN_AUDIT_ENABLED=true`, 서버 전용 키와 승인된 개발 프로젝트 URL을 확인합니다. 기능은 기본 비활성이며 환경변수·키는 설정하지 않았습니다. 기존 관리자 간 세분화된 역할 구분은 없습니다.

`supabase/drafts/day19_activity.sql`은 기존 다섯 유형의 이력과 인덱스를 조회하고 이력 조회 자체를 별도 테이블에 기록하는 **검토용 초안**입니다. 조회자 ID·이력 유형·시각만 남기며 결과와 조회 기록을 같은 트랜잭션에서 처리하므로 기록이 실패하면 결과를 반환하지 않습니다. 익명·일반 인증 역할의 실행을 차단하고 서버 전용 서비스 역할만 함수를 호출합니다. 이력 조회 기록의 열람·보존·삭제 정책과 화면은 아직 없습니다.

**빠진 기록:** 강좌·기수 변경, 신청·문의 목록 검색, 로그인 시도, 데이터 내보내기와 서비스 키로 DB에 직접 접근한 행위는 이 화면에 기록되지 않습니다. 각 이력의 변경 전후 전체 내용은 보관하지 않으며, 이전에 기록되지 않은 행위를 복원할 수 없습니다. 같은 서비스 역할 키 보유자는 앱 검사를 우회하거나 일부 기록을 위조할 수 있으므로 위변조 방지 감사 시스템이 아닙니다. 감사 범위·관리자별 권한·별도 보관 및 이상 징후 탐지를 실제 운영 전에 결정해야 합니다.

## 개인정보 수동 처리 절차 초안

자동 삭제는 실행하거나 예약하지 않습니다. 삭제 버튼, 자동 만료와 익명화 기능도 아직 없습니다. 다음은 기관의 정책 확정과 검토를 위한 절차이며 실제 작업 지시나 법률 판단이 아닙니다.

1. 기관은 신청·문의별 보존 목적과 기간, 보존 예외·보류, 처리 기한, 담당자와 승인자를 확정합니다. 보존 기간을 임의로 추정하지 않습니다.
2. 요청을 접수하면 승인된 별도 채널에서 요청 유형과 대상 식별·권한을 확인합니다. 이름·연락처·본문을 GitHub, 채팅, URL 또는 공개 로그에 복사하지 않습니다.
3. 담당자가 최소 권한으로 관련 신청·문의와 이력의 연관 관계 및 보존 예외를 확인합니다. 신청은 기수 정원·중복 신청 규칙에 영향을 줄 수 있고, 이력과 개인정보 테이블에는 삭제 제한 외래키가 있습니다. 단순 행 삭제나 외래키 해제로 우회하지 않습니다.
4. 승인자가 대상·범위·보류 여부·백업과 복구 영향을 검토합니다. 실제 삭제 방식은 별도 설계·검증 및 승인 후 실행합니다. 현재 코드에는 실행 가능한 삭제 수단이 없습니다.
5. 실행 기능이 마련된 후에는 권한 있는 담당자가 결과를 확인하고, 필요한 최소한의 처리 사실과 승인·완료 시각을 보호된 장소에 남깁니다. 백업·로그·복원본의 처리는 별도 보존·복구 정책에 따라 추적하며, 한 곳에서 삭제했다고 모든 사본이 삭제됐다고 단정하지 않습니다.
6. 확인 실패나 처리 결과 불확실 시 반복 삭제하지 않고 작업을 중지해 책임자에게 확인합니다. 실제 데이터로 연습하지 않으며 가상 데이터와 격리 환경만 사용합니다.

8~19일차 SQL은 실제 개발 DB에 적용하지 않았습니다. 적용 전 현재 객체·권한·마이그레이션 이력, 이력 누락과 역할 범위를 확인하고 별도 승인 후 개발 DB에서 실제 관리자 계정·Data API·RLS를 검증해야 합니다. 개인정보 수집·보존·삭제와 접근 기록 정책, 백업 삭제·복원 절차는 기관이 확정해야 합니다. 기존 `public.rls_auto_enable()` 보안 경고 2건은 미해결입니다. 운영 DB, 다른 Supabase 프로젝트, `main`, 운영 배포는 변경하지 않았습니다.
