# 백엔드 9일차: 공개 기수·일정 연결

작성일: 2026년 11월 7일

상태: **화면·공개 정책 초안과 격리 검증 완료 — 실제 개발 DB 적용과 API 검증 대기**.

## 결정과 현재 상태

- 공개 기준은 사용자가 선택한 **관리자가 공개로 지정한 일정만**입니다. 초안은 기본값이 `false`인 공개 여부를 두고, 공개된 강좌에 속한 작성 중이 아닌 일정만 공개합니다. 공개 설정을 변경하는 관리자 화면은 10일차에 구현해야 합니다.
- 개발 검증에는 사용자가 선택한 기존 일정 예시 5개를 사용합니다. 날짜·장소·정원은 예시이며 실제 모집 정보로 이관하지 않습니다. 예시의 가상 신청 인원은 DB에 넣지 않습니다. 정원 임박 기준은 미정이므로 `마감임박` 예시는 저장할 때 `open`으로만 표시합니다.
- 개발 DB에는 현재 강좌와 기수가 없고 공개 읽기 권한이 없습니다. 8일차 강좌 공개 정책과 예시 데이터도 아직 적용 전입니다. 이번 작업에서 DB·권한·데이터를 변경하지 않았습니다.

## 준비한 변경

- 홈페이지 일정 카드, 교육일정 달력·목록과 강좌 상세에서 일정으로 이동하는 링크가 같은 서버 데이터 원본을 사용합니다. 기본값은 예시 화면이며 `ACADEMY_COURSE_SOURCE=supabase`에서만 공개 뷰를 조회합니다. `ACADEMY_SCHEDULE_DEMO_DATA`가 `false`가 아닌 경우 예시 안내를 유지합니다.
- 실제 데이터 모드에서 날짜·장소 미정과 빈 결과를 표시하고, API 오류나 잘못된 날짜는 오류 화면으로 처리합니다. 조회 실패 시 예시 일정으로 자동 대체하지 않습니다. 실제 신청 기능과 신청 인원은 아직 연결하지 않아 가상의 신청 인원이나 신청 버튼을 표시하지 않습니다.
- 화면의 모집 상태는 DB에 저장된 상태를 보여 주는 것이며 날짜 경계, 정원 잔여 수, 자동 마감이나 실제 접수 가능 여부를 계산하지 않습니다. 이들 규칙은 11~13일차 구현과 검증이 필요합니다.
- `supabase/drafts/day09_public_offerings.sql`은 공개 여부 필드, RLS·필요 열 권한과 `security_invoker` 뷰의 **검토용 초안**입니다. 8일차 공개 강좌 초안이 선행되어야 하며, 실제 적용 전 기존 객체와 anon/authenticated 접근 범위를 다시 확인해야 합니다.
- `supabase/drafts/day09_dev_offerings.sql`은 8일차의 공개 예시 강좌 5개가 있고 기수 테이블이 비어 있을 때만 예시 일정 5개를 넣는 **개발 전용 초안**입니다. 트랜잭션 내 잠금과 선행 조건 검사를 포함합니다.

## 검증과 남은 작업

`npm run test:course-access` 및 `npm run test:schedule-access`는 메모리 PostgreSQL 17에서 8일차 강좌의 공개·비공개 회귀, 일정의 공개 지정·부모 강좌 상태·쓰기 차단, 예시 일정의 날짜·장소·정원 일치, 날짜 미정과 시드 선행 조건을 확인합니다. 가상 공개 API와 격리 브라우저에서 홈페이지, 달력·목록, 과정별 필터, 모바일 가로 폭, 빈 결과, 잘못된 날짜와 API 오류를 확인했습니다. 실제 Supabase Data API 검증은 아닙니다.

실제 연결 전에는 먼저 8일차의 공개 강좌 변경과 예시 데이터를 개발 DB에 적용할 범위를 확정하고 검증해야 합니다. 이후 9일차 초안의 공개 정책·뷰 및 개발용 일정 데이터를 검토하고, 개발 DB에서 익명·인증 사용자별 공개·비공개·쓰기 차단과 실제 API·화면을 검증해야 합니다. 운영 적용 전 관리자 공개 변경 및 실접수 정책이 별도로 필요합니다.

기존 `public.rls_auto_enable()` 경고 2건과 미적용 보안 마이그레이션 초안, 실제 관리자 계정 검증은 별도 작업으로 남아 있습니다. 운영 DB와 `main`은 변경하지 않았습니다.
