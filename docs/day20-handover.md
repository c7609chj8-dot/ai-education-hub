- 프로젝트: `C:\Projects\ai-education-hub`, GitHub: [ai-education-hub](https://github.com/c7609chj8-dot/ai-education-hub), 브랜치 `main`.

## 시연 동작과 제외 범위

- 공개 화면은 `/`, `/about`, `/programs`, `/schedule`, `/outcomes`, `/news`, `/resources`, `/faq`, `/partnership`, `/contact`와 과정 상세로 구성됩니다.
- `/apply/[offeringId]`와 `/contact`의 입력 검사는 시연입니다. 유효한 값을 입력해도 실제 접수·메일 발송·저장은 일어나지 않습니다. 개인정보 대신 가상 정보만 사용합니다.
- `/admin/demo`와 강좌·일정·가상 신청·브랜드 설정 하위 화면은 인증 없이 열리는 시연입니다. 편집 내용은 관리자 시연의 브라우저 메모리에만 유지되며 화면을 벗어나거나 새로고침하면 사라집니다. 실제 개인정보를 입력하지 않습니다.
- 일정·모집 상태·후기·신청 항목은 예시입니다. 대표 이미지와 결과물 이미지 일부는 AI 생성 예시로 표시합니다. 자료실은 실제 파일을 제공하지 않습니다. 실제 연락처·주소·기관 정보와 운영 일정은 확정 후 반영해야 합니다.
- 실제 DB/API, 관리자 인증·권한, 개인정보 저장, 정원 관리, 파일 업로드, 결제와 문자·이메일 발송은 구현하지 않았습니다. 현재 코드에는 Supabase 연결이나 그 환경변수가 없습니다.

## 검수 증거와 남은 문제

- 2026년 11월 7일 `npx tsc --noEmit`, `npm run lint`, `npm run build` 통과.
- Vercel 운영 주소의 19일차 배포본에서 360px로 25개 경로를, 768·1440px로 주요 10개 경로를 확인했습니다. 세 크기에서 강좌 검색→상세→일정→신청 시연과 브랜드 미리보기 초기화가 통과했습니다. 모바일에서 문의 입력 검사, 관리자 편집·새로고침 초기화와 입력의 전송·저장 여부도 확인했습니다. 잘못된 일반·강좌·기수 주소는 404를 반환했습니다.
- 19일차 로컬 운영 빌드 검수와 위험도는 [DAY 19 검수 보고서](day19-review.md)에 있습니다. npm 감사에서 개발 의존성 중간 등급 경고 8건이 남아 있고, 운영 의존성 감사는 0건이었습니다. 제안된 주요 버전 변경은 호환성 확인 없이 적용하지 않았습니다.
- 관리자 인증이 없는 시연 화면에 실제 신청자 데이터나 개인정보를 넣어서는 안 됩니다. 실제 서비스 전환은 별도 백엔드 설계와 검수가 선행되어야 합니다.

## 배포 후 Supabase 연계 계획

현재는 연결하지 않았습니다. 다음 단계에서 별도 범위와 환경을 정해 아래 순서로 진행합니다.

1. 실제 수강신청·상담·관리자의 업무 흐름, 필수 데이터와 보존 기간을 확정합니다.
2. 개발과 운영 환경을 분리하고 강좌·기수·신청 등의 데이터 모델과 마이그레이션을 설계합니다. 모집 정원과 중복 신청은 서버 측에서 일관되게 처리하도록 설계합니다.
3. 관리자 인증·역할과 데이터별 접근 정책을 설계합니다. 노출되는 테이블의 RLS와 접근 권한을 함께 검증하고, 비밀 키를 브라우저에 두지 않습니다.
4. 신청·문의 저장과 관리자 화면을 연결한 뒤 성공·실패·권한 없는 접근·동시 신청·개인정보 처리 흐름을 검수합니다. 파일·알림은 필요한 범위가 정해진 후 별도로 연결합니다.
5. Vercel의 개발·미리보기·운영 환경변수와 배포 절차를 분리하고, 실제 운영 정보와 개인정보 안내를 확정한 뒤 검수합니다.

연결 시점의 최신 문서와 변경 사항을 다시 확인합니다: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [API 키](https://supabase.com/docs/guides/getting-started/api-keys), [변경 내역](https://supabase.com/changelog).
