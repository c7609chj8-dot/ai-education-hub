# 백엔드 14일차: 관리자 신청 목록과 확인 처리

작성일: 2026년 11월 8일

상태: **관리자 화면·서버 처리와 DB 초안 준비, 격리 검증 완료. 실제 개발 DB 적용과 실제 신청자 검증은 대기.**

## 결정과 구현 범위

- 기관이 선택한 상태는 `접수 → 확인`입니다. 확인 처리도 정원을 계속 차지하며, 교육 참여 확정이나 결제 완료를 뜻하지 않습니다. 취소·반려·정원 복귀·재신청은 정책이 미정이므로 제공하지 않습니다.
- `/admin/console/applications`는 서버에서 인증된 사용자와 관리자 ID 허용목록을 확인합니다. 검색과 확인 처리도 요청마다 별도로 확인합니다. 기능 설정 `ACADEMY_ADMIN_APPLICATIONS_ENABLED=true`, 서버 전용 키와 개발 프로젝트 URL이 갖추어진 경우에만 DB 호출을 시도합니다. URL은 승인된 개발 프로젝트 `uenvjqgylrevujdjpfed`로 고정되어 있으며 기능은 기본적으로 꺼져 있습니다. 이번 작업에서 환경변수나 키를 설정하지 않았습니다.
- 이름 또는 연락처 끝 네 자리로 검색하고 이름의 첫 글자와 연락처 끝 네 자리만 보여 줍니다. 검색어는 주소창에 넣지 않고 요청 본문으로 전송합니다. 한 페이지에 최대 20건씩 표시하며 접수 시각과 ID를 이용해 다음 페이지를 조회합니다. 필요한 최소 항목에 대한 정책 검토 전까지 전체 연락처 표시·내보내기는 제공하지 않습니다.
- 확인 처리 시 클라이언트가 지정한 담당자 ID는 사용하지 않습니다. 같은 서버 검증에서 얻은 관리자 사용자 ID와 DB의 기록 시각을 상태 변경과 함께 저장하고 목록에 표시합니다. 저장 응답 오류 시 성공으로 단정하지 않고 다시 조회하도록 안내합니다.

## DB 초안과 정원

`supabase/drafts/day14_admin_applications.sql`은 **검토용 초안**입니다. 8~12일차 초안을 선행하며 신청 상태, 이력 테이블, 마스킹 검색과 확인 함수를 추가합니다. 이력에는 신청 ID·담당자 ID·변경 전후 상태·시각만 기록하며 이름과 연락처는 복제하지 않습니다. 이력 저장이 실패하면 상태 변경도 롤백됩니다. RLS를 활성화하고 anon/authenticated의 함수 실행을 차단하는 초안입니다.

기존 `supabase/drafts/day12_atomic_applications.sql`의 신청·관리자 정원 집계 두 곳을 `received`와 `reviewed`를 모두 세도록 수정했습니다. 두 초안은 함께 검토해야 합니다. 이력은 서비스 역할이 쓰는 일반 DB 기록이며, 고권한 비밀 키를 가진 주체까지 위조·변조할 수 없는 감사 저장소를 의미하지 않습니다. 목록 조회 자체의 접근 이력은 아직 구현하지 않았습니다.

실제 서버 키는 프로젝트 전반에 높은 권한을 가지므로 키와 Data API 접근을 별도로 보호해야 합니다. 검색어·신청 식별자·개인정보가 애플리케이션 및 플랫폼 로그에 남지 않는지 실제 연결 전에 점검해야 합니다.

## 검증

- `npm run test:admin-applications`: 비로그인·일반 사용자, 빈 기능 설정, 다른 프로젝트 URL을 차단하고 마스킹 형식·페이지 커서·위조된 담당자 ID를 검사했습니다.
- `npm run test:application-concurrency`: 별도 로컬 PostgreSQL 17의 두 연결에서 익명·인증 사용자 함수 호출 차단, 이력 실패 시 롤백, 확인 후 정원 보존, 동시 확인 시 이력 한 건, 동일 시각의 25건 페이지 이동과 기존 신청 경합을 확인했습니다.
- 별도 복사본에서만 개발 URL 고정을 로컬 모의 서버로 바꾸고, 가상 Auth·API와 브라우저로 관리자 검색·확인, 캐시 방지, 비로그인·일반 사용자의 직접 요청 차단, 기능 비활성화를 확인했습니다. 이는 실제 Supabase 로그인·API 검증이 아닙니다.
- TypeScript, ESLint, 전체 빌드와 기존 신청·관리자·강좌·일정 회귀 검사를 실행했습니다.

## 실제 사용 전 남은 작업

8~14일차 SQL은 실제 개발 DB에 적용되지 않았습니다. 적용 전 현재 객체·권한·마이그레이션 이력과 롤백을 확인하고 개발 DB에 대한 별도 적용 절차 및 실제 관리자 계정·RLS·API 검증이 필요합니다. 개인정보 수집·보존·삭제, 담당자 권한과 접근 이력·감사 보존, 취소·반려 정책을 기관이 확정해야 합니다. 기존 `public.rls_auto_enable()` 보안 경고 2건은 미해결입니다. 기존 보안 마이그레이션 초안, 운영 DB, `main`과 운영 배포는 변경하지 않았습니다.
