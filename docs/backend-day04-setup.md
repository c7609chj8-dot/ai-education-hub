# 백엔드 4일차 개발 환경 준비 현황

작성일: 2026년 11월 7일

상태: **부분 완료 — 실제 개발 DB 생성과 Supabase 마이그레이션 검증 대기**. 이 문서는 `codex/backend-day04` 작업 브랜치의 진행 기록입니다.

## 준비한 항목

- Supabase CLI `3.0.0`을 프로젝트 개발 의존성으로 정확한 버전으로 고정하고 npm 잠금 파일에 반영했습니다.
- `supabase init`으로 로컬용 `supabase/config.toml`을 생성했습니다. 새 public 테이블의 API 자동 노출은 끄고 아직 준비되지 않은 시드 실행도 비활성화했습니다. 원격 프로젝트 연결값이나 비밀키는 추가하지 않았습니다.
- `supabase/drafts/course_foundation.sql`에 개인정보가 없는 강좌·주차·기수의 비공개 기초 스키마를 **검토용 초안**으로 작성했습니다. 접근 정책은 기본 거부이며 신청·문의 테이블이나 실제 데이터는 포함하지 않습니다. 기수 상태 등 미확정 정책은 향후 수정할 수 있습니다.
- `supabase/drafts/course_foundation_check.sql`에 RLS 활성화, 공개 역할의 스키마 접근 제한, slug·주차 중복, 정원·날짜와 외래키 제약을 확인하는 테스트를 준비했습니다. 테스트 데이터는 트랜잭션 롤백으로 남기지 않습니다.
- 초안과 검수 SQL은 임시 메모리 기반 PostgreSQL 호환 엔진 PGlite 0.5.15에서 실행해 통과했습니다. **이는 실제 Supabase나 마이그레이션 재현 검증을 대신하지 않습니다.** PGlite는 검수용 임시 도구이며 프로젝트 의존성에 추가하지 않았습니다.
- 기존 프런트엔드의 타입 검사·ESLint·빌드가 통과했습니다. npm 감사 결과는 19일차와 같은 중간 등급 8건, 높음·심각 0건이었습니다.

## 진행을 막는 환경 상태

1. 사용자가 개발용 프로젝트 대상 조직으로 `time`을 선택했습니다. `ai-education-hub-dev` 생성을 요청했으나 Supabase가 **계정의 무료 활성 프로젝트 한도(2개)**에 도달했다고 응답하여 생성되지 않았습니다. 별도 비용 조회에서는 월 0달러로 반환됐지만, 이 값이 한도 해제나 향후 요금을 보장하지는 않습니다. 사용자는 무료 프로젝트 한도를 확보하는 방식을 선택했으나, 확보 완료는 아직 확인되지 않았습니다. 기존 프로젝트를 중지·삭제하거나 요금제를 변경하지 않았습니다.
2. Docker Desktop은 설치되어 있으나 Linux 엔진에 연결되지 않았습니다. 백그라운드 시작을 시도해도 엔진이 준비되지 않아 로컬 Supabase를 시작하거나 실제 Supabase DB에서 초안을 적용·검증하지 못했습니다.
3. 따라서 `supabase/migrations`에 적용 가능한 마이그레이션을 생성하지 않았고, 앱·Vercel에 개발 DB를 연결하지 않았습니다. 공개 사이트의 신청과 문의는 시연 상태입니다.

## 이어서 진행할 절차

1. 기관에서 Supabase 무료 프로젝트 한도 문제를 해결하거나, Docker Desktop을 실행 가능한 상태로 준비합니다. 기존 다른 프로젝트의 중지·삭제나 요금제 변경은 해당 프로젝트 소유자가 판단해야 합니다.
2. 확인된 **개발 전용** 환경의 프로젝트·비용·대상 연결을 다시 확인합니다. 운영 DB 또는 기존 다른 프로젝트에 검토용 SQL을 적용하지 않습니다.
3. 개발 DB에서 초안을 적용하고 `course_foundation_check.sql`과 보안·성능 점검을 실행합니다. 정책이 미확정인 항목은 검수 후 수정합니다.
4. CLI의 실제 버전과 로컬/원격 대상 옵션을 확인해 검증된 상태에서 마이그레이션을 생성하고, 빈 개발 환경에서 재적용·재현성을 확인합니다. CLI v3는 기본 대상이 로컬이므로 원격 변경 시 대상을 별도로 확인합니다.
5. RLS·공개 읽기 정책, 관리자 역할과 신청·문의 개인정보 구조는 이후 확정된 요구사항과 5일차 보안 검수에 맞춰 별도로 구현합니다.
