# B-03-5 관리자 교육일정 저장 후보

2026-11-09 점검. 기준 PR #27 / `869e49f814c9ef0bd7960cd6423d0e79042e35a2`. 대상 개발 DB는 `ai-education-hub-dev` / `uenvjqgylrevujdjpfed`. **관리자 RPC·권한은 실제 DB에 적용하지 않았다.**

후속 보안 검토: 현재 후보는 `service_role`의 직접 테이블 쓰기로 RPC 검증을 우회할 수 있다. 격리 DB에서 구체적으로 재현했으며 실제 Auth 로그인도 아직 검증되지 않았다. 적용 전 `docs/backend-b03-5-auth-security-review.md`를 먼저 확인한다.

## B-03-4 실제 적용 확인

개발 DB에 기존 4건의 이력과 `20261108143123_public_offerings_catalog`, `is_public`, 공개 SELECT 정책 및 `security_invoker=true` 뷰가 존재한다. 이력에 분리 저장된 7개 SQL 문장은 주석·공백·세미콜론 제거 후 Git 후보와 일치했다. 바이트 단위 일치나 적용 당시 dry-run/실행 로그는 확인하지 않았다. 실제 익명 API는 강좌 5개·주차 60개·일정 0개를 각각 HTTP 200으로 반환했다. `anon`·`authenticated`의 기수 쓰기 권한은 카탈로그상 없고 Security Advisor 결과는 0건이었다. PR #27 설명에도 사후 확인을 기록했다.

후속 DB 점검에서 강좌 5개·주차 60개·기수 0개와 Auth 사용자 1명을 확인했으며 강좌·주차 전체 행 해시는 B-03-3 점검 시점과 같다. 이후 Security Advisor에 유출 비밀번호 보호 비활성화 WARN 1건이 표시됐다. 기존 공개 RLS 및 강좌 데이터를 수정하지 않았다.

## 준비한 관리자 기능

- 관리자 기수 폼은 강좌, 교육 시작·종료일, 모집 시작·마감, 장소, 정원, 진행 상태, 공개 여부를 입력한다. 새 기수는 공개 체크가 기본 해제된다. 미정 일정은 비공개 `draft`로만 저장하며 모집기간은 둘 다 입력하거나 둘 다 비워야 한다. 공개 또는 draft가 아닌 기수는 교육일·모집기간을 모두 요구하고, 모집 중 정원은 1 이상이어야 한다.
- `src/lib/admin/seoul-time.ts`는 브라우저와 서버의 기본 시간대를 쓰지 않고 `Asia/Seoul` 벽시각과 UTC 시각을 상호 변환한다. 달력상 존재하지 않는 시각, 시간대 전환에서 건너뛰거나 두 번 발생하는 시각은 거부한다. 입력 초 단위 정밀도로 제한하고 API의 유효하지 않거나 0이 아닌 소수 초 응답은 목록을 실패 처리해 편집 시 시각이 조용히 잘리지 않게 한다.
- 새 등록에는 클라이언트 요청별 UUID를 사용하고 처리 결과 불명 시 화면에서 반복 제출을 막는다. DB 후보는 UUID 충돌과 **모든 일정 속성이 같은** 중복을 거부하며, 같은 내용의 동시 저장은 트랜잭션 advisory lock으로 직렬화한다. 같은 강좌라도 날짜·장소·정원 등 내용이 다르면 별개 일정으로 저장할 수 있다.
- 기존 서버 액션에서 입력 검증과 관리자 확인을 하고, 서비스 클라이언트도 매번 `getAdminAccess()`를 다시 호출한다. 이 함수는 Supabase Auth `getUser()`로 확인한 사용자 ID와 서버 전용 `ACADEMY_ADMIN_USER_IDS`를 비교한다. `ACADEMY_ADMIN_MANAGEMENT_ENABLED=true`, 개발 프로젝트 URL 및 서버 전용 키가 없으면 실패한다. 사용자 메타데이터를 관리자 권한으로 사용하지 않는다.
- 관리자 기수 페이지는 다른 기존 관리자 기능과 분리된 `academy_admin_offerings_catalog_v1`, `academy_admin_save_offering_v1`를 사용한다. 현재 DB에 이 함수들이 없어 실제 저장 기능은 사용 불가다. 공개된 기존 기수 조회를 위해 개발 예시 기수를 등록하지 않았다.

## SQL 후보와 권한·의존 관계

`supabase/migrations/20261108162624_admin_offering_management.sql`은 미적용 후보이며 정규화 SHA-256(UTF-8 CRLF→LF, 양끝 공백 제거)은 `16de60a8b7c67dc91f063bbcff0bc2b0813850d0a4f295af34c9e769e69925ab`이다.

| 변경 대상 | 제안 |
| --- | --- |
| 두 새 RPC | `SECURITY INVOKER`, 빈 `search_path`. PUBLIC·anon·authenticated EXECUTE 회수, `service_role`에만 EXECUTE |
| `academy` | `service_role`에 USAGE |
| `academy.courses` | 서비스 역할에 ID·제목·공개 상태 SELECT만 부여. 강좌 쓰기 권한 없음 |
| `academy.offerings` | 서비스 역할에 필요한 열의 SELECT·INSERT·UPDATE만 부여. DELETE 미부여. 익명·인증 역할의 기존 ACL과 RLS는 변경하지 않음 |

`service_role`은 RLS를 우회하는 강한 역할이며 제안된 열 권한으로 RPC를 통하지 않는 직접 쓰기도 가능하다. 보안 경계는 **서버 전용 키 보호와 매 요청 인증·ID 허용목록 검사**에 의존한다. 일반 사용자에게 키를 노출하거나 이 권한만으로 관리자 인가가 된다고 가정하면 안 된다.

현재 DB에는 기존 `academy_admin_save_offering*`이나 신청 테이블이 없다. 후보 사전 검사는 이들 또는 충돌 함수·예상 밖 서비스 권한이 존재하면 중단한다. 후보 함수도 신청 테이블이나 다른 같은 계열 함수가 나중에 나타나면 저장을 중단한다. 다만 향후 다른 DB 경로가 생기면 새 함수의 검사를 우회할 수 있으므로, 기존 day10/day12 초안을 그대로 함께 배포하지 않는다. 실제 신청 기능을 연결하기 전 신청 인원에 따른 정원 축소·강좌 변경·잠금 순서와 서비스 직접 쓰기 경로를 다시 설계하고 별도 승인받아야 한다. 공개 강좌 상태를 동시 변경하는 미래 관리자 기능도 경합 검증 대상이다.

## 빌드와 Tailwind

`npm run build`는 기존 Turbopack CSS loader의 Node 자식 프로세스 연결 오류로 실패했다. `npx next build --webpack`은 종료 코드 0이지만 결과 CSS에 `.w-full`, `.p-5`, `.bg-brand-navy`가 없고 `@theme`이 남았다. 따라서 대체 빌드 통과도 화면 정상이나 배포 가능을 뜻하지 않는다. UI 시각·반응형 검수도 미실시다.

최소 수정 후보는 별도 격리 작업에서 Next.js 문서의 `@tailwindcss/postcss` 설정과 기존 Turbopack loader의 역할을 비교하고, 의존성·설정을 조정한 뒤 두 빌드의 유틸리티 CSS와 주요 화면을 재검증하는 것이다. 설정 변경은 이번 PR에 포함하지 않았다.

## 실제 DB 적용 전 조건·복구

1. SQL과 서비스 역할 권한 확대, 정확한 중복 기준, 직접 서비스 키 우회 범위를 검토하고 **별도 승인**을 받는다.
2. 개발 프로젝트 ID·기존 이력 4건·함수 충돌·신청 테이블 부재·기존 ACL·데이터 해시·후보 SHA를 재확인한다. 단일 트랜잭션 보장이 확인된 Session Pooler 경로의 dry-run에서 이 후보 1건만 확인한다. CLI dry-run과 실제 DB 적용은 아직 하지 않았다.
3. 이상이 있거나 적용이 실패·타임아웃되면 추가 변경 및 재실행을 중단하고 이력·함수·ACL·실제 행을 읽기 전용으로 확인한다. 실제 함수가 이미 적용됐으면 재실행하지 않는다.
4. 문제 발생 시 기존 데이터와 서비스 의존성을 보존하며, 적용 전 저장한 함수·ACL 상태를 기준으로 표적 권한 복원 또는 정방향 수정 계획을 별도 승인받는다. 기존 기수나 강좌를 삭제하지 않는다.
5. 실제 관리자 테스트 계정·허용목록·서버 전용 키, 브라우저 및 공개 상태 변화 검증이 준비되고 빌드·CSS 문제가 해결되기 전에는 운영 기능으로 간주하지 않는다.

실제 DB 변경, 예시 기수 등록, 신청 기능 활성화, 다른 Supabase 프로젝트·main·Vercel Production 변경은 하지 않았다.
