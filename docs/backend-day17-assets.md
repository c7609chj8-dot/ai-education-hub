# 백엔드 17일차: 교육자료·성과 파일 관리

작성일: 2026년 11월 8일

상태: **관리·공개 화면과 SQL 초안 준비, 격리 검증 완료. 실제 DB·Storage에는 적용하지 않았습니다.**

## 구현 범위

- 관리자 `/admin/console/assets`에서 교육자료와 성과 이미지의 파일을 등록하고 제목·설명·공개 여부를 수정합니다. 파일은 기본 비공개이며 관리자가 공개로 지정한 항목만 공개 목록에 표시합니다. 관리 요청마다 관리자 ID를 재확인하고 동시 수정 충돌을 감지합니다. 업로드 결과가 불확실하면 중복 등록을 막고 확인을 안내합니다. 삭제 기능은 제공하지 않습니다.
- 저장 경로는 임의의 UUID로 만들며 원래 파일명은 사용하지 않습니다. PDF·PNG·JPEG·WebP, 최대 2MiB만 허용하고 성과 파일은 이미지로 제한합니다. 서버가 본문 크기, 선언된 형식과 파일 서명을 확인합니다. 이는 완전한 파일 해석이나 악성코드 검사가 아닙니다.
- 공개 파일은 비공개 버킷에서 서버를 통해 내려받고 캐시하지 않습니다. 응답은 첨부파일 다운로드로 제한하며 파일 내용을 브라우저에 바로 표시하지 않습니다. 이미지 미리보기는 아직 제공하지 않습니다. 공개 취소 전에 이미 시작된 요청은 완료될 수 있습니다.
- `academy-assets` 버킷이 비공개인지 관리자 업로드, 공개 전환 및 공개 다운로드 직전에 확인하며 확인되지 않으면 거부합니다. 실제 버킷을 만들거나 설정하지 않았습니다. 이 검사만으로 다른 관리자에 의한 버킷 설정 변경이나 직접 노출을 방지할 수 없으므로 운영자는 별도 접근 정책과 설정 점검이 필요합니다.
- 기본 공개 화면은 기존 시연 내용을 유지합니다. 개발 환경에서 `ACADEMY_ASSET_SOURCE=supabase`와 `ACADEMY_PUBLIC_ASSETS_ENABLED=true`를 설정하면 지정된 개발 프로젝트의 공개 자료만 목록에 표시합니다. 관리자 기능도 `ACADEMY_ADMIN_ASSETS_ENABLED=true`, 개발 프로젝트 URL, 서버 전용 키가 필요합니다. 이번 작업에서 환경변수와 키는 설정하지 않았습니다. 서버 전용 키는 프로젝트 전체에 고권한이 있으므로 엄격히 관리해야 합니다. 공개 목록은 유형별 200개를 초과하면 오류로 처리하며 관리자 목록은 20개씩 표시합니다.

## SQL 초안과 데이터

`supabase/drafts/day17_assets.sql`은 자료 메타데이터와 변경 이력, 공개 목록 뷰, 서버 전용 함수의 검토용 초안입니다. 공개 역할이 파일 저장 경로를 직접 조회하지 않도록 설계했습니다. 관리자 이력은 고권한 키 보유자까지 변조를 막는 감사 저장소가 아닙니다. 버킷 생성·Storage 정책 변경은 포함하지 않습니다.

업로드 성공과 메타데이터 기록 사이에 오류가 나면 비공개 버킷에 연결되지 않은 파일이 남을 수 있습니다. 자동 재시도나 삭제를 하지 않으므로 활성화 전에 확인·대조·정리 절차를 마련해야 합니다. 실제 파일과 가상 파일을 Supabase에 업로드하지 않았습니다.

## 검증 및 남은 작업

- `npm run test:asset-database`: 별도 로컬 PostgreSQL에서 비공개 기본값, 역할별 차단, 공개·비공개 변경, 동시 편집 충돌과 이력 기록 실패 시 롤백을 확인했습니다. Storage 검사는 포함하지 않습니다.
- `npm run test:asset-services`: 가상 PDF와 저장소 모의 응답으로 파일 검사, 요청·응답 크기 제한, 관리자·출처 확인, 비공개 버킷 확인과 공개 다운로드 헤더를 검사했습니다. 실제 Supabase 서비스 검증은 아닙니다.
- 별도 복사본과 가상 인증·저장소로 브라우저에서 비공개 업로드, 공개·비공개 전환, 안전한 다운로드, 일반 사용자 직접 요청 차단, 크기·형식 오류, 저장 결과 불확실 시 재시도 차단과 기본 시연 모드를 확인했습니다. 실제 Supabase 검사가 아닙니다.
- TypeScript, ESLint, 빌드와 기존 콘텐츠·문의 서비스 회귀 검사를 수행했습니다.
- 실제 운영 전에는 파일 출처·저작권과 공개 승인, 악성코드 검사, 안전한 형식 변환 및 이미지 메타데이터 제거, 남은 파일 정리, 요청 남용 방지와 모니터링을 마련해야 합니다. 현재 형식 서명 검사는 파일의 안전성이나 정상 재생을 보장하지 않습니다.
- 8~17일차 SQL은 개발 DB에 적용하지 않았습니다. 기존 객체·마이그레이션·Storage 설정을 점검하고 별도 승인 후 개발 환경에서 실제 관리자 인증, Storage API, RLS·권한, 파일 공개·회수 흐름을 검증해야 합니다. 기존 `public.rls_auto_enable()` 보안 경고 2건은 미해결입니다. 운영 DB, 다른 Supabase 프로젝트, `main`과 운영 배포는 변경하지 않았습니다.
