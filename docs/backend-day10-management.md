# 백엔드 10일차: 강좌·기수 관리자 관리

작성일: 2026년 11월 7일

상태: **관리 화면과 서버 처리, SQL 초안 및 격리 검증 완료. 실제 개발 DB 반영과 실제 인증·API 검증 대기.**

## 구현 범위

- `/admin/console/courses`에서 강좌 등록·수정 및 작성 중/공개/보관 상태를 설정합니다. `/admin/console/offerings`에서 기수의 강좌, 일정, 장소, 정원, 진행 상태와 공개 여부를 설정합니다. 삭제와 주차 관리, 실제 수강신청은 이 작업 범위에 없습니다.
- 관리자 화면 진입과 각각의 서버 액션, 데이터 접근 시 서버에서 검증한 사용자와 `ACADEMY_ADMIN_USER_IDS` 허용목록을 확인합니다. 환경변수 `ACADEMY_ADMIN_MANAGEMENT_ENABLED`가 정확히 `true`이고 유효한 프로젝트 설정과 서버 전용 `SUPABASE_SECRET_KEY`가 모두 있을 때만 데이터 호출을 시도합니다. 설정 누락, 로그인·권한 불일치, API 오류는 닫힌 상태로 처리합니다.
- 키는 서버 전용으로 사용하며 브라우저에 전달하지 않습니다. **Supabase secret key는 프로젝트 전반에 대한 높은 권한을 가지며, 함수의 SQL 권한 제한만으로 키 자체가 제한되는 것은 아닙니다.** 유출 방지·최소 보관·교체 및 운영 접근 통제가 필요합니다. 기능 활성화 값과 키는 이번 작업에서 설정하거나 발급하지 않았습니다.
- 공개 기수는 공개 강좌에 속해야 하며 작성 중인 기수는 공개할 수 없습니다. 강좌를 비공개로 변경하면 기존 공개 기수도 조회에서 숨겨지지만 기수의 공개 지정은 유지되므로 강좌 재공개 시 다시 노출될 수 있습니다. 저장 시 날짜 순서, 정원, 필수 값 등도 검증합니다. 신청 인원 집계·동시 접수·정원 차감과 상태 자동 전환은 구현하지 않았습니다.

## DB 초안과 선행 조건

`supabase/drafts/day10_admin_management.sql`은 **검토용 초안**이며 원격 DB에 실행하지 않았습니다. 8일차의 objectives와 강좌 공개 정책, 9일차의 기수 공개 여부와 정책이 먼저 필요합니다. 함수 3개는 `SECURITY INVOKER`로 작성하고 anon/authenticated 실행을 차단하며 `service_role`에만 실행과 필요한 열 권한을 부여하도록 초안에 명시했습니다. 저장 요청은 서버 관리자 검사 후에만 이 함수를 호출합니다. 기수 공개 시 부모 강좌의 상태를 트랜잭션 중 잠금으로 확인합니다.

실제 적용 전에는 개발 프로젝트 ID, 현재 객체·기존 권한·마이그레이션 이력과 8·9일차 선행 초안의 적용 범위를 재검토하고, 권한 영향과 롤백 계획을 확인해야 합니다. 8·9·10일차 SQL은 현재 미적용이며 실제 관리자 계정, secret key 설정, 원격 함수 호출과 실제 Data API 권한·브라우저 검사는 미검증입니다. 이 문서는 개발 DB 적용을 승인하는 문서가 아닙니다.

## 검증

- `npm run test:admin-management`: 격리된 메모리 PostgreSQL 17에서 함수 3개의 실행 권한, 일반 역할 직접 실행 차단, 서비스 역할의 등록·수정, 공개·숨김, 잘못된 날짜·정원 및 비공개 강좌의 공개 기수 차단을 확인했습니다.
- `npm run test:admin-validation`: 서버 입력의 유효성, 중복 필드, 잘못된 ID·날짜·정원·상태와 작성 중 기수 공개 차단을 확인했습니다.
- `npm run test:course-access`, `npm run test:schedule-access`: 기존 강좌·일정 공개·비공개 규칙과 쓰기 차단을 격리 DB에서 회귀 검증했습니다.
- 가짜 인증/API와 격리 브라우저에서 관리자 강좌·기수 등록·수정·공개 전환, 일반 사용자의 페이지와 직접 저장 요청 차단, 기능 비활성화 시 호출 차단 및 화면에서 키 미노출을 확인했습니다. 이는 실제 Supabase 검증이 아닙니다.
- TypeScript, ESLint, Next.js 빌드를 확인했습니다.

기존 `public.rls_auto_enable()` 관련 보안 경고 2건은 미해결이며 이번 작업에서 수정하지 않았습니다. 실제 관리자 계정 검증, 변경 이력·감사, 동시 편집 충돌 처리, 실제 접수 및 정원 관리, 운영 적용 절차는 후속 작업입니다. 운영 DB와 `main`은 변경하지 않았습니다.
