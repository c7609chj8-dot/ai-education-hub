# 에이담 AI아카데미 백엔드 구축 작업계획서

작성일: 2026년 11월 7일
대상: 기존 Next.js 프런트엔드, GitHub, Vercel, Supabase
상태: 제안 계획. 일정과 세부 운영 정책은 착수 시 확정합니다.

## 1. 목표와 현재 상태

현재 [시연 사이트](https://ai-education-hub-ten.vercel.app)는 강좌·일정·성과·공지와 신청·문의·관리자 화면을 제공하지만, 신청과 문의는 실제로 접수되지 않고 관리자 화면에도 인증이 없습니다. 데이터는 예시이며 Supabase 연결은 없습니다. GitHub `main` 푸시는 Vercel 운영 배포를 자동으로 시작합니다. 이전 결과와 검수 내역은 [프런트엔드 인수인계](day20-handover.md)와 [19일차 검수 보고서](day19-review.md)를 참고합니다.

목표는 실제 강좌·기수 운영, 안전한 수강신청과 문의, 권한 있는 관리자 관리 기능을 갖춘 서비스로 전환하는 것입니다. 기존 데모가 실제 접수로 오인되지 않도록 실제 기능의 준비와 검수가 끝날 때까지 시연 표시를 유지합니다.

## 2. 범위와 전제

### 기본 범위

- **공개 교육정보:** 강좌·주차별 교육내용·기수·공지·FAQ·성과·교육협력 정보를 데이터 기반으로 표시하고, 운영자가 공개 여부를 관리합니다.
- **실제 수강신청:** 기수별 신청 접수·중복 방지·정원 확인·접수 결과·취소 및 관리자 처리 상태를 지원합니다. 정확한 중복 기준과 취소 규칙은 확정이 필요합니다.
- **문의:** 필요한 항목만 수집하고, 실제 접수 결과와 관리자 확인·처리 상태를 제공합니다.
- **관리자:** 로그인, 역할별 권한, 강좌·기수·신청·문의·콘텐츠·브랜드 관리와 작업 이력을 제공합니다. 실제 관리자 화면은 기존 `/admin/demo`와 분리합니다.
- **자료·이미지:** 자료와 성과 이미지는 실제 파일만 연결하며, 공개 자료와 비공개 자료의 접근 권한을 분리합니다.
- **운영 준비:** 개발·미리보기·운영 환경, 백업·복구, 오류 관찰, 접근성·보안·성능·인수 검수 및 전환 절차를 마련합니다.

### 별도 결정 또는 추가 일정

결제·환불·현금영수증, 문자·이메일 자동 발송, 수강생 계정과 본인인증, 출석·수료증, 온라인 강의 재생, 외부 LMS 연동은 기능·제공업체·요금·정책이 정해지지 않았으므로 기본 25일 산정에 포함하지 않습니다. 필요할 경우 별도 요구사항과 견적을 추가합니다. 기본 범위에서는 신청 완료를 화면에서 안내하고, 신청 내역 확인 방식은 운영 정책에 따라 확정합니다.

## 3. 권장 구성

| 영역 | 계획 | 비고 |
| --- | --- | --- |
| 프런트엔드 | 기존 Next.js 화면을 유지하고 실제 데이터와 성공·실패·빈 상태 연결 | 시연 화면과 실제 운영 화면을 명확히 구분 |
| 서비스 처리 | Next.js 서버 측 처리와 필요한 DB 트랜잭션을 이용 | 서버 측 입력 검증·권한 검사·오류 처리 |
| 데이터 | Supabase Postgres와 버전 관리되는 마이그레이션 | 개발과 운영 데이터를 분리하고 백업·복구 검증 |
| 관리자 인증 | Supabase Auth와 서버 측 권한 검사 | 로그인 자체와 관리자 권한 판단을 분리 |
| 권한 | 비공개 데이터는 기본 거부, 필요한 역할·행만 허용 | Data API 노출·GRANT와 RLS를 함께 점검 |
| 파일 | Supabase Storage 사용 여부와 공개·비공개 버킷 정책 결정 | 업로드 유형·크기와 다운로드 권한 검증 |
| 배포 | Vercel Preview에서 먼저 검수하고 Production으로 전환 | `main` 자동 배포를 고려해 기능 비활성 기본값과 데이터 환경 분리 |

관리자 인증은 요청마다 서버에서 검증하며 클라이언트 화면 숨김이나 사용자 수정 가능 메타데이터만으로 권한을 결정하지 않습니다. 브라우저에 노출되는 공개 키는 권한을 보장하지 않으므로 RLS 및 접근 정책이 필요하며, 서비스 역할·비밀 키는 브라우저나 Git에 넣지 않습니다. Next.js와 Supabase의 세션·키 처리 방식은 착수 시 최신 공식 문서를 다시 확인합니다. [Supabase 서버 측 인증](https://supabase.com/docs/guides/auth/server-side/creating-a-client?queryGroups=framework&framework=nextjs) · [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) · [API 키](https://supabase.com/docs/guides/getting-started/api-keys)

## 4. 데이터 및 권한 설계 초안

테이블명은 확정안이 아니라 설계 출발점입니다. 개인정보 항목·관계·보존 기간은 운영 정책 확정 후 마이그레이션으로 구현합니다.

| 데이터 | 주요 내용 | 공개 방문자 | 관리자 |
| --- | --- | --- | --- |
| 강좌·커리큘럼 | 과정명, 설명, 분야, 주차 내용, 공개 상태 | 공개된 항목만 조회 | 권한에 따른 생성·수정·공개 |
| 기수 | 기간, 장소, 정원, 모집 상태 | 공개된 항목만 조회 | 권한에 따른 등록·변경 |
| 신청 | 기수, 최소 신청 정보, 동의 이력, 처리 상태 | 정책에 맞는 접수만 허용; 타인 목록 조회 금지 | 필요한 범위에서 조회·처리 |
| 문의 | 문의 유형·내용, 최소 연락 정보, 동의 이력, 상태 | 정책에 맞는 접수만 허용; 타인 목록 조회 금지 | 필요한 범위에서 조회·처리 |
| 콘텐츠·파일 | 공지·FAQ·결과물·파일 메타데이터 | 공개된 항목만 조회 | 권한에 따른 관리 |
| 관리자·감사 이력 | 역할, 변경 대상·시각·수행자 | 접근 불가 | 최소 권한으로 조회·운영 |

서버 또는 DB에서 신청 가능 상태와 중복 여부를 다시 검사합니다. 남은 자리가 하나일 때 동시 요청이 와도 정원을 넘지 않도록 하나의 트랜잭션과 적절한 잠금 또는 동등한 원자적 처리로 접수하고, 재시도 시 중복 접수를 막는 기준도 정의합니다. 테스트에서는 마지막 자리 경쟁, 반복 전송, 취소 후 재신청, 마감 상태 변경을 검증합니다.

## 6. 단계별 완료 기준

1. **설계 완료:** 수집 항목, 동의·보존, 역할, 기수·정원·취소 규칙 및 관리자 접근 범위를 문서로 확정합니다.
2. **개발 환경 완료:** 테스트 데이터만 사용해 마이그레이션을 다시 적용할 수 있고 인증·RLS·기본 접근 차단이 확인됩니다.
3. **핵심 기능 완료:** 강좌 조회부터 신청·문의 접수, 관리자 확인까지 실제 데이터 흐름이 작동합니다. 실패했는데 완료로 표시하지 않습니다.
4. **운영 준비 완료:** 동시 신청, 중복 전송, 권한 우회, 파일 접근, 개인정보 노출, 백업 복원, 모바일·키보드 접근을 검수합니다. 고위험 결함을 해결합니다.
5. **운영 전환:** 별도 Preview 검수와 운영 데이터 준비를 마친 후 전환하고, 핵심 흐름을 다시 확인합니다. 장애 시 사이트 이전 버전 복구와 DB 복구 절차를 구분해 준비합니다.

## 7. 운영·보안·배포 검수 항목

- 실제 개인정보는 개발·테스트에서 사용하지 않고, 수집 최소화·접근 기록·보존 및 삭제 기준을 운영자가 정합니다.
- 노출 테이블의 접근 GRANT와 RLS를 검토하고, 비관리자·다른 사용자·로그아웃·만료 세션에 대한 접근 차단을 테스트합니다.
- 신청·문의는 서버 검증과 요청 제한·오용 방지 방안을 적용하며, 오류 로그와 화면에 개인정보·비밀 값이 남지 않도록 점검합니다.
- 파일의 공개 범위·업로드 허용 형식·크기·다운로드 권한을 검증합니다.
- 정원 초과, 중복 요청, 실패 후 재시도, 신청 취소와 기수 상태 변경을 동시성 테스트로 확인합니다.
- 운영 반영 전 백업과 테스트 복원, 마이그레이션 적용·실패 시 복구, 프런트엔드 롤백 절차를 준비합니다. 프런트엔드 롤백이 DB를 자동으로 되돌리지는 않습니다.
- 현재의 정적 강좌·기수 경로와 404 처리는 실제 데이터 기반 운영에 맞게 재설계합니다. 기존 개발 도구 의존성의 중간 등급 감사 경고 8건도 호환성을 확인해 처리하거나 수용 근거를 기록합니다.
- Vercel 환경별 비밀값은 플랫폼에서 관리하고 저장소에 기록하지 않습니다. Preview가 운영 DB에 쓰지 않도록 확인합니다. [Vercel 환경 문서](https://vercel.com/docs/deployments/environments)

## 8. 착수 전 결정 사항

| 항목 | 결정할 내용 | 일정에 미치는 영향 |

| 신청·정원 규칙 | 중복 기준, 대기자, 취소 기한, 정원 산정과 수동 처리 방식 | DB 트랜잭션·관리 기능 범위 결정 |
| 개인정보 | 필수 항목, 동의 문구, 보존 기간, 삭제·열람 담당 | 스키마와 권한·운영 절차 결정 |
| 관리자 | 담당자 수, 권한 구분, 초기 계정·복구 절차 | 인증·역할 설계 결정 |

| 계정과 비용 | Supabase/Vercel 소유 계정, 환경 분리, 예상 트래픽, 요금 한도 | 프로젝트 구성과 운영비 산정에 필요 |
